# SpaceLink 기획안 (서울 맞춤 주택·상가·오피스 추천 서비스)

> 노션 통합 기획안 + 화면설계서(화면 33개) 기준. 최종 수정 2026-11-17

## 1. 서비스

SpaceLink는 사용자 조건을 분석해 서울의 청약 공고와 조건에 맞는 집·상가·사무실을 추천하고, 판단 근거와 주변 환경 정보를 함께 보여 주는 포트폴리오 서비스입니다.

- **1순위:** 아파트, 오피스텔, 도시형생활주택, 민간임대, 무순위·잔여세대, 공공분양·공공임대 공고
- **2순위:** 집 화면은 청약 공고와 주거용 공매를 함께 보여 줌. 매매·전월세 실거래와 건물 정보는 상세의 주변 시세·추천 점수 근거로 사용하며, 실제 매물 중개·계약은 하지 않음
- **상가:** 공공 상가 공고 + 업종별 입지·건물 분석. 매물 데이터는 공매 물건만 다루고, 신청 버튼은 공공 공고(공급기관 공식 신청 페이지)와 공매(온비드 입찰 페이지)에만 둠
- **사무실(오피스):** 업무시설 입지·건물 분석. 주거용 오피스텔과 구분. 매물 데이터는 공매 물건만 다루고, 신청 버튼은 공공 공고와 공매에만 둠
- **공매:** 온비드 공매 물건(서울)을 집·상가·오피스 목록에 건물 분석 결과와 함께 표시하고 "공매" 라벨로 구분. 별도 공매 화면은 두지 않음
- **사용자:** 청년, 신혼부부, 유자녀 가족, 노부부, 독거노인, 자영업자, 프리랜서
- **서비스 역할:** 예상 자격, 예상 가점, 맞춤 추천, 판단 근거 제공. 청약 신청 대행, 공매 입찰 대행·권리 분석, 공식 자격 확정, 수익·창업 성공 예측, 매물 중개·계약은 하지 않음
- **개발 기간:** 2026-11-18 ~ 2026-12-18 (2인 팀)

## 4. 기능

| 기능 | 내용 |
| --- | --- |
| 회원가입·로그인 | 아이디·비밀번호 가입과 구글·네이버·카카오 로그인. 일반·소셜 가입 모두 공통 정보 입력에서 아이디·비밀번호·닉네임·생년월일을 설정하고 약관 동의 후 가입한다. 소셜 인증에서 확인된 이메일은 자동 입력하고 직접 가입은 이메일 인증을 진행한다. 청약 정보 조회는 가입과 분리한다. 필수·선택 약관과 선택 동의 저장 방식은 기존 기준을 유지하고, 5회 실패 시 잠금·비밀번호 BCrypt 저장을 적용 |
| 아이디·비밀번호 찾기 | 아이디는 가입 이메일로 안내 메일(템플릿) 발송. 비밀번호는 보내지 않고 재설정 링크(30분·1회용, 토큰 해시는 Redis에 30분 TTL로 저장하고 사용하면 삭제) 발송. 가입 여부가 드러나지 않게 같은 안내 문구 사용 |
| 맞춤 청약 조건 | 첫 이용 때 기관·요청자료 선택 → 제공 동의 → 간편인증 → 기관별 요청·수신 → 조회 결과 확인 → 저장 순서로 진행한다. 기관별 완료·실패 상태와 실패 항목 다시 불러오기를 제공하고 전체 결과는 읽기 전용으로 확인한다. 시연 구현은 내부 가상 응답을 사용하며 실제 기관에 요청하지 않는다. 구현용 가상 응답 안내를 사용자 화면에 표시하지 않는다. 필요한 정규화 값만 저장하고 마이페이지에서 최신 조회 결과 확인·재조회·삭제가 가능하다. 외국인은 신청 가능한 청약이 제한될 수 있음을 안내한다 |
| 찾는 대상·희망 조건 | 맞춤 추천·상가·오피스 첫 이용 때 입력. 사용자 유형은 앞 단계에서 한 번 선택해 저장하되, 매물 기본 점수는 사용자 유형이 아닌 집·상가·오피스별 고정 가중치로 계산한다. 집·상가·오피스 희망 조건은 유형별로 각각 한 세트씩 입력·저장하고 수정한다. 공통 정보는 SEARCH_PREFERENCE에, 유형별 조건과 생성·수정일시는 HOUSE_PREFERENCE·STORE_PREFERENCE·OFFICE_PREFERENCE에 나눠 저장한다. 같은 유형을 수정·저장하면 해당 유형만 갱신하고 다른 유형 조건은 유지한다. 추천에는 대상 유형에 맞는 조건을 사용 |
| 맞춤 추천 | 대상별 공고 목록(예상 자격·청약 가점 별도 표시)과 건물 목록(매물 추천 점수·근거 표시), 사용자가 지정한 조건·자연어 선호를 반영한 개인화 추천, AI 추천 사유 |
| 지도 | 공공 데이터 좌표를 저장해 네이버 지도에 핀 표시(상태별 색상, 클러스터). 청약 목록 지도는 기존 SUB_LIST-01에서 제공하고, 통합 매물 지도는 PROP_MAP-01에서 제공. 네이버 지도가 들어가는 화면(매물 지도, 청약 목록, 집·상가·오피스 목록, 후보 비교)은 공통으로 확대·축소·지도 유형 전환, 핀 선택 시 거리뷰 보기와 길찾기(네이버 지도 웹·앱 새 창 연결)를 제공 |
| 매물 지도 | 집·상가·오피스 매물(공매 포함)과 현재 모집 중인 청약·공공 공고를 한 지도에 핀으로 표시한다. 유형별 필터, 지도 이동에 따른 범위 검색, 마커 클러스터를 제공하고 핀을 누르면 해당 상세 화면으로 이동한다. |
| 메인 홈 | 빠른 검색(지역·유형·접수 상태), 하이브리드 AI 검색·추천, 매물 Top 5(조회수 기준 접수 중 매물 상위 5개를 아래에서 위로 한 개씩 롤링. 조회수는 대상별 조회 수 칼럼에 상세 조회 때마다 더함), 알고리즘 추천 카드 5~6개(3개씩, 이전·다음), 바로가기·공지 |
| 청약 | 수집처와 수집처 공고 번호를 조합해 공고를 식별하고, 같은 공고를 다시 받으면 기존 행의 변경 정보를 갱신. 목록 + 지도(면적 필터·카드 면적은 공고별 최소·최대 전용면적 사용), 메인 홈 일정 캘린더, 내 조건 기준 보기, 공고 상세(기본정보, 모집 일정, 예상 자격·가점, 가격·면적, 주변 환경, 준비서류 안내(공고문 제출서류를 텍스트로 표시), 공식 원문) |
| 집 | 서울 청약(분양·공공임대) 공고를 집 목록으로 표시(건물명·지역 검색, 지역·공급 유형·가격·면적·접수 상태 필터, 추천·마감 임박·가격순), 희망 조건 기준 추천 점수. 주거용 공매 물건 함께 표시. 상세는 청약 정보(공급 유형·공급 규모·주택형·분양가·접수 기간·당첨자 발표·예상 자격·예상 가점) + 건물 상세 공통 구성. 신청은 청약홈 신청 페이지(새 창), 공매는 온비드 입찰 페이지로 이동 |
| 상가 | 전체 / 공공 상가 공고 / 일반 건물 분석 / 공매 구분(전체에서 건물 분석 결과·공공 공고·공매 함께 표시), 업종별 지역 추천(상권 점수). 상세는 건물 상세 공통 구성 참조. 공공 공고는 공급기관 공식 신청 페이지로, 공매는 온비드 입찰 페이지로 이동하는 버튼을 제공 |
| 오피스 | 전체 / 공공 오피스 공고 / 일반 건물 분석 / 공매 구분(전체에서 건물 분석 결과·공공 공고·공매 함께 표시), 입지 점수. 상세는 건물 상세 공통 구성 참조. 공공 공고는 공급기관 공식 신청 페이지로, 공매는 온비드 입찰 페이지로 이동하는 버튼을 제공 |

- **기관별 청약정보 조회 흐름:** 기관·자료 선택과 제공 동의 후 간편인증 입력·대기·완료를 진행하고 선택한 기관별 요청·수신 상태를 표시합니다. 간편인증은 이름·생년월일·휴대폰 번호 등 인증에 필요한 항목을 입력하는 화면으로 구성하되 실제 인증·기관 호출은 하지 않고 가상 응답으로 흐름을 검증합니다. 기존 단일 import API는 기관 선택·동의·인증·기관별 수신 상태를 포함하도록 개편하고, 구체적인 API 경로는 상세 설계에서 확정합니다. 실제 기관 응답은 승인된 묶음정보·API 규격에 맞춘 어댑터에서 내부 프로필 모델로 변환합니다.
- 내부 응답에는 요청 기관·자료, 조회 기준 시각과 항목별 완료·실패·결과 없음 상태를 둡니다. 개발용 가상 응답 표식은 서버 내부에서 관리하며 사용자 화면에 시연용·기관 미연동 문구를 표시하지 않습니다. 미수신 또는 실제 제공 여부·판정 근거가 확인되지 않은 항목은 자격 계산에서 확정값으로 취급하지 않고 ‘확인 필요’로 표시합니다. 주민등록번호·인증서·서류 원문은 저장하지 않습니다.
- 사용자는 조회 결과를 읽기 전용으로 확인하고 저장 버튼으로 필요한 정규화 값만 `SUBSCRIPTION_PROFILE`에 저장합니다. 원문 JSON·증빙 문서는 저장하지 않습니다. `UPDATED_AT`은 조회 결과를 프로필에 저장한 시각입니다. 다시 불러오기는 재조회이며, 마이페이지에는 저장된 최신 결과의 요약·확인 필요 상태·조회 시각을 표시합니다. 공고일 기준 자격 규칙 엔진이 예상 자격·가점을 계산하고 AI는 설명·추천 이유만 작성합니다. 현재 구현은 실제 공공기관 조회나 공식 자격 검증을 제공하지 않습니다.
- 실제 연계 검토는 행정안전부 공공 마이데이터의 제공요구 가능 본인정보 목록과 서비스 수행 가이드, 이용기관 신청 절차를 기준으로 합니다. 현재 공개 목록에서 주민등록표, 가족관계증명서, 소득금액증명, 부동산·건축물·자동차 자료와 일부 세금·보험 자료는 확인할 수 있지만, 이는 SpaceLink가 해당 자료를 바로 호출할 수 있다는 뜻이 아닙니다. 묶음정보 승인과 제공 필드, 정보주체별 동의 범위를 확인해야 합니다.
- 원천정보가 청약 판단용 구간을 바로 제공한다고 가정하지 않습니다. 주택 보유 이력·세대 전체 부동산/총자산, 자동차 기준가액, 모든 공급기관의 당첨 이력은 자료 범위와 산식 검증이 필요합니다. 청약통장 납입 횟수·금액은 공개된 제공요구 가능 본인정보 목록에서 확인되지 않아 금융기관 등 별도 경로가 필요할 수 있습니다. 이 항목은 실제 출처가 확정되기 전까지 `ASSUMPTION`으로만 시연합니다.
- 시연용 계정 4개를 미리 만들고 계정마다 가상 행정정보를 다르게 연결해, 예상 자격 4단계가 모두 나오게 합니다: 청년 1인(생애최초 가능성 있음, 신혼부부 특공 해당 없음), 신혼부부(맞벌이 소득 기준선 근처로 확인 필요), 다자녀·노부모 부양(가점 높음), 유주택·고소득(대부분 불가). 조회 결과가 없는 항목은 판정하지 않고 '확인 필요'로 표시합니다.
- 자동차는 차량 기준가액 합계 구간으로 판정합니다. 합계 구간 전체가 기준 이하면 통과, 초과면 미달, 기준선에 걸치거나 공고가 합산이 아닌 다른 계산 방식이면 ‘확인 필요’로 표시합니다.
- 생년월일·내외국인·청약 프로필·희망 조건을 바꾸면 예상 자격과 추천을 다시 계산합니다.
- 집·상가·오피스 희망 조건은 유형별로 각각 한 세트씩 저장·수정합니다. SEARCH_PREFERENCE에는 회원 ID와 공통 사용자 유형을 저장하고, HOUSE_PREFERENCE·STORE_PREFERENCE·OFFICE_PREFERENCE에는 해당 유형의 조건과 CREATED_AT·UPDATED_AT을 저장합니다. 세부 테이블은 회원당 한 행이며, 설정하지 않은 유형은 세부 행을 만들지 않습니다. 유형을 바꿔 편집·저장하면 해당 유형의 행만 생성 또는 갱신하고 나머지 유형 조건과 수정일시는 유지합니다. 추천에는 조회 대상 유형의 세부 조건을 사용합니다.
- 보유 주택은 주소 없이 공시가격 합계 구간만 저장합니다.
- 테이블은 MEMBER, SUBSCRIPTION_PROFILE, SEARCH_PREFERENCE, HOUSE_PREFERENCE, STORE_PREFERENCE, OFFICE_PREFERENCE로 나눕니다. SUBSCRIPTION_PROFILE은 MEMBER에 종속하고, SEARCH_PREFERENCE는 SUBSCRIPTION_PROFILE의 MEMBER_ID를 참조합니다. 유형별 희망 조건 테이블은 SEARCH_PREFERENCE의 MEMBER_ID를 참조하며, 각 테이블은 공통 설정 또는 유형별 조건을 회원당 최대 한 행으로 저장합니다. 유형별 생성·수정일시는 각 상세 테이블에서 관리하고, 전체 희망 조건의 마지막 변경 시각은 필요하면 세부 행 UPDATED_AT의 최댓값으로 조회합니다.

## 7. 메인 홈 AI 검색·추천과 맞춤 배너

- **하이브리드 검색:** 필터(지역·유형·접수 상태)는 빠른 검색으로 청약 목록에 이동하고, 문장 질문은 AI 검색·추천으로 처리합니다. 예: "성동구 신혼부부가 넣을 만한 공고", "아이 키우기 좋은 조용한 동네"
- **흐름:** 질문(개인정보 마스킹) → OpenAI가 조건으로 변환 → Tool Calling → PKG_RECOMMEND가 후보와 순위 계산 → SSE로 답변과 추천 카드를 홈에 표시. 답변 중지와 추가 질문 가능
- **대화 저장 안 함:** AI 검색·추천과 AI 고객상담 대화는 DB에 저장하지 않습니다. 페이지에 있는 동안만 화면이 대화를 기억해 질문할 때 함께 보내고, 페이지를 벗어나면 초기화합니다. 마음에 드는 카드는 찜으로 남깁니다. AI 고객상담 → 1:1 문의 전환은 그 자리에서 요약을 문의 작성 화면으로 넘깁니다
- **Tool Calling:** searchListings(공고·집·상가·오피스 검색), searchNoticeDocs(공고문 RAG), checkEligibility(자격 판단 결과와 근거), getSchedule(접수·마감 일정). Tool은 조회만 하고, 카드는 Tool이 돌려준 ID로 Web이 만듭니다
- **AI 역할 제한:** OpenAI는 조건 변환, Tool 선택, 추천 이유 작성만 맡습니다. 회원 식별은 요청 토큰으로 처리해 모델에 보내지 않고, 소득·자산·가족 정보는 보내지 않습니다
- **고객센터 AI 고객상담과는 별개입니다.** AI 고객상담은 계정·로그인, 알림, 오류, 탈퇴, 데이터 출처 등 웹사이트 이용 문의만 답하고, 공고·청약 자격 질문은 청약 목록·공고 상세로 안내합니다

학습은 모델 학습이 아니라 사용자 행동을 DB에 기록해 점수에 반영하는 방식입니다. 아래 수치는 모두 시작값입니다.

| 행동 | 점수 |
| --- | --- |
| 카드 클릭 | +1 |
| AI 검색·조건 검색 | +2 |
| 상세 조회 | +3 |
| 관심 등록 | +5 |
| 관심 없음 표시 | -5 |

- **집계:** 지역, 주택 유형, 거래 유형, 가격대별로 쌓고, 30일이 지나면 점수를 절반으로 줄입니다.
- **보관:** 원본 기록은 90일만 보관하고, 탈퇴하면 삭제합니다. 행동 기록 수집은 가입 때 선택 동의로 받아 회원의 행동 기록 수집 동의 칸에 저장하고, 동의하지 않으면 기록하지 않습니다(질문 원문은 저장하지 않음).
- **배너 점수:** 기본 추천 점수 × (1 - a) + 행동 선호 점수 × a. 행동 기록이 5건 미만이면 a는 0, 5~29건이면 0.15, 30건 이상이면 0.3입니다. 이 배너 계산은 11절의 현재 검색 선호 개인화 점수와 별도 단계로 적용하며, 배너 점수는 메인 홈 카드 정렬에 사용합니다. 이 배너 계산은 11절의 현재 검색 선호 개인화 점수와 별도 단계로 적용하며, 배너 점수는 메인 홈 카드 정렬에 사용합니다.
- **카드 구성:** 자격이 불가·해당 없음이거나 마감된 공고는 제외하고, 공고·건물·상가 칸을 나눕니다. 카드마다 추천 이유를 표시합니다. 메인 홈 알고리즘 추천은 카드 5~6개를 3개씩 보여 주고 이전·다음 버튼으로 넘깁니다.
- **추천 정렬:** 자격 가능성(신청 자격이 될 것 같은 공고 먼저) → 개인 취향(찜·클릭 등 행동 기록으로 계산한 맞춤 배너 점수, 기록이 없으면 이 단계는 건너뜀) → 현재 거주지와 가까운 공고 순. 비로그인은 최신·마감 임박 공고로 채웁니다.
- **구현:** USER_EVENT, USER_BANNER_CARD 테이블을 쓰고, 하루 1회 배치로 계산합니다. 행동 선호 점수는 따로 저장하지 않고 배치에서 USER_EVENT를 바로 집계합니다. 회원 정보와 연결되므로 WEB_APP 계정으로 실행합니다.

## 8. 알림과 이메일

- **수집·알림 흐름:** Data는 수집처(SOURCE)와 수집처 공고 번호(SOURCE_NOTICE_NO)의 조합으로 기존 공고를 찾아 신규 등록 또는 변경 정보 갱신을 합니다. 변경이 확인되면 조건 승인 상태를 다시 확인 필요로 돌리고, Web 스케줄러가 매칭·알림을 처리합니다.
- **사이트 내 알림(이연화):** SSE로 전송합니다. DB에 먼저 저장하고, 재연결 때 놓친 알림을 다시 보냅니다. 헤더에 안 읽은 알림 수 표시
- **이메일(정려립):** NOTIFICATION에서 대상을 읽어 발송하고 결과를 기록합니다. 맞춤 알림 수신 동의 회원만 대상입니다.
- **추천 공고 메일:** 새 추천이 있을 때만 보내고(없으면 발송하지 않음), 한 메일에 최대 5건을 요약 + 링크로 보냅니다. 이미 보낸 공고는 다시 보내지 않습니다. 필요하면 관련 안내 문서를 Google Docs로 첨부하고, 공고 원문 파일은 링크로 안내합니다.
- **따로 보내는 메일:** 정정 공고, 찜 공고 접수 시작·마감 D-1, 당첨 발표, 문의 답변, 마케팅 정보(마케팅 수신 동의 회원만), 아이디 안내·비밀번호 재설정 링크(템플릿)
- **메일 원칙:** 소득·자산 등 판정 근거는 넣지 않고, 하단에 알림 설정·수신 거부 링크를 넣습니다.
- **중복 방지:** 회원, 알림 유형, 대상의 조합에 유니크 제약을 겁니다.

## 9. 공고 조건 승인과 공고문 처리

- **흐름:** AI가 공고문에서 조건 초안을 만들면 승인 대기로 저장하고, 관리자가 원문·AI 추출값·최종값을 대조해 승인한 조건만 자격 판단에 씁니다.
- **관리자 화면:** 대기 목록, AI 초안과 공고문 링크, 수정 입력칸, 승인·반려(사유 필수) 버튼. 비정상 값이나 빈 필수 항목은 자동 강조
- **승인 전:** 공고는 사이트에 보여 주고, 자격 판단은 ‘확인 필요’로 표시합니다. 정정 공고가 수집되면 다시 ‘확인 필요’로 돌립니다.
- **담당:** 정려립은 관리자 화면, 팀장은 조건 추출과 자동 검사, 자격 판단을 맡습니다.
- **합의 필요(초안):** 조건 테이블(공고 ID, 항목, AI 추출값, 최종값, 원문 위치), 상태 값(대기, 승인, 반려)
- **첨부파일 범위:** 주택(청약·공공 임대)·상가·오피스 공고와 온비드 공매의 공고문과 첨부파일(호실·주택형 표, 감정평가서 등)을 모두 수집해 공고문·첨부 파일 테이블에 저장합니다(PDF, HWP, HWPX, XLSX, 스캔). 청약 공고는 자격 조건(소득·자산·자동차·무주택·거주·청약통장)을, 상가·오피스 공고는 입점·입주 자격, 업종 제한, 임대 기간, 보증금·임대료 조건, 호실별 조건과 호실 목록(공급 단위)을, 공매는 입찰 제한·제출 서류·지분·권리 관계 안내를 추출하며, 모두 관리자가 확인한 값만 화면에 표시합니다.
- **공고문 처리:** Data가 공고문 파일을 수집하고, 자격 표 페이지를 찾아 300dpi 이미지로 자른 뒤, AI가 Spring AI와 gpt-5.4-mini로 조건 초안을 만들고, 관리자가 승인하면 Web의 Java 규칙이 자격을 판단합니다.
- **파일 범위:** PDF 민영·공공분양 공고부터 처리하고, 아래한글과 스캔본은 그다음에 붙입니다. 항목마다 AI 추출값과 원문 위치를 저장합니다. 공고문의 제출서류 부분도 같은 단계에서 텍스트로 뽑아 공고에 저장하고, 관리자가 조건과 함께 확인합니다.
- **RAG:** 공고문은 조각내어 문서 벡터 테이블에 저장하고, 자격 판단과 점수에는 쓰지 않습니다.
- **Python:** 페이지 이미지 생성과 자르기는 PDFBox(Java)로 처리하고, 이 방식으로 안 될 때만 Python을 씁니다.
- **검증:** 공공분양 3건은 시험했고, 표 자동 자르기와 민영·아래한글·스캔본이 남았습니다.

## 11. 매물 추천 점수 기준 및 계산 예시

매물 용도별 기본 가중치는 SCORE_WEIGHT에서 관리하며, 집·상가·오피스 각각의 합계는 100점이다. (SPACE_CATEGORY, FACTOR) 조합은 중복될 수 없다. 회원이 저장한 개인 선호 가중치는 MEMBER_SCORE_WEIGHT에서 회원·용도·평가 항목별로 관리하며, 회원·용도별 합계는 30점이다. 현재 검색에서만 쓰는 선호는 저장하지 않는다. 청약 프로필의 자격 판단·청약 가점은 매물 추천 점수와 별도 결과로 표시한다.

점수 갱신: 항목별 평가점수와 최종 추천 점수는 Oracle에 저장하지 않고, 검색 요청 때 원천 데이터와 용도별 기본 가중치·회원 선호 가중치·현재 검색 조건으로 계산한다. 동일한 대상·용도·가중치·조건 및 데이터 기준의 계산 결과는 Redis에 캐시한다. 원천 데이터, 평가 규칙, 기본 가중치, 회원 선호 또는 검색 조건이 바뀌면 관련 캐시를 갱신한 뒤 다시 계산한다. 주변 환경 요약은 PLACE_ENV에 저장하고 계산 일시를 관리한다.

가격 비교 대상: 현재 모집 중이거나 모집 예정으로 화면에 노출되는 후보 중 같은 지역·용도·거래 유형의 후보끼리 ㎡당 가격을 비교한다. 비교 후보 수가 부족하거나 서로 다른 가격 구간을 나눌 수 없으면 가격은 ‘확인 필요’로 표시하고 해당 후보의 점수 계산에서 가격 가중치를 제외한다.

### 11.1 기본 점수 가중치 근거와 계산법

#### 1. 기본 점수 가중치와 근거

매물 추천 점수는 집·상가·오피스의 입지와 조건을 100점 만점으로 평가한다. 청약프로필은 예상 청약 자격과 청약 가점 산정에 사용하며, 화면에서는 매물 추천 점수와 각각 표시한다.

##### 집·상가·오피스 · 매물 용도별 기본 가중치

기본 가중치는 매물 용도에 따라 한 세트씩 적용한다. 같은 매물에 같은 검색 조건을 적용하면 기본 점수도 같다. 거주 인원과 업무 인원은 추천 후보의 필수 조건이며, 업종은 해당 평가 항목의 입력으로 사용한다.

| 매물 용도 | 교통 | 인프라 | 안전 | 학군 | 소음 | 침수 | 악취 | 가격 | 상가 업종별 상권 | 유동인구 | 상가 업종 적합도 | 오피스 업종 적합도 | 합계 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 집 | 18 | 16 | 13 | 6 | 14 | 11 | 6 | 16 | — | — | — | — | 100 |
| 상가 | 10 | — | — | — | 5 | 10 | 10 | 15 | 20 | 15 | 15 | — | 100 |
| 오피스 | 25 | 10 | 10 | — | 15 | 10 | 10 | 15 | — | — | — | 5 | 100 |

‘—’는 해당 용도의 평가 항목에서 제외한다는 뜻이다. 상가는 프론트에서 선택한 희망 업종을 업종별 상권 20과 업종 적합도 15에 적용한다.

- **집**은 이전 7개 유형의 항목별 가중치를 같은 비중으로 평균 내고 정수로 반올림했다.
- **상가**는 업종별 상권 20과 유동인구 15로 영업 입지를 평가하고, 업종 적합도 15로 매물의 공간·설비를 평가한다.
- **오피스**는 교통·가격에 40을 배정해 출퇴근 접근성과 비용을 중심으로 평가한다.

매물 용도별 적용과 상가·오피스의 소음·침수·악취 반영은 확정 규칙이다. 표의 가중치를 적용한다. 상가와 오피스 모두 시설 피해 및 영업·업무 중단 가능성을 반영해 침수에 10을 배정하고, 고객·근무자의 이용 환경을 반영해 악취에도 10을 배정했다. 오피스는 소음이 집중과 통화·회의에 직접 영향을 주므로 15를 배정했다. 상가에서는 상권·인구를, 오피스에서는 교통·인프라·가격·상권을 각각 5씩 줄여 합계 100을 맞췄다. 기존 오피스 상권 5는 업종 적합도에 배정했다.

#### 2. 확정된 계산 규칙

0. 집과 오피스는 인원 조건을 먼저 확인한다. 요청 인원을 수용하는 매물만 점수 계산과 추천 정렬에 포함한다. AI 채팅·검색에서 입력한 인원에도 같은 기준을 적용한다.
1. 각 항목과 하위 지표의 기준 만점은 100점이다. 입력값에 평가 기준을 적용해 0~100점의 평가점수를 산정한다. 교통은 **지하철역과 버스정류장 접근성**, 학군은 **학교 접근성만** 반영한다.
2. 인프라는 아래 8종 시설의 평가점수를 배점으로 가중평균한다. 병원 등 일반 시설 6종은 가까울수록 점수가 높거나 같다. 경기장과 체육관은 적정 거리에서 가점을 주고, 지나치게 가까우면 소음 우려를 반영해 적정 거리보다 낮은 평가점수를 부여한다.
3. 자료가 누락된 항목이나 하위 지표는 해당 단계의 분자와 분모에서 함께 제외한다. 확인된 0점은 유효한 값으로 계산에 포함한다. 시설 부재가 확인된 경우에는 해당 부재의 점수 기준을 적용하고, 자료 부족 상태와 구별한다.
4. 유효 가중치 합이 0이면 해당 단계의 점수를 산출할 수 없다. 하위 지표가 전부 누락된 항목은 최종 집계에서 제외한다. 최종 단계에서도 합이 0이면 화면에 **계산 자료 부족**으로 표시한다. 중간값은 유지하고 최종 표시 점수만 소수점 첫째 자리로 반올림한다.

| 인프라 시설 | 병원 | 마트 | 주민센터 | 복지센터 | 구청 | 시청 | 경기장 | 체육관 | 합계 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 시설별 배점 | 20 | 20 | 15 | 15 | 5 | 5 | 10 | 10 | 100 |

병원·마트·주민센터·복지센터에 총 70점을 배정해 일상 이용 편의를 우선한다. 구청·시청은 총 10점, 경기장·체육관은 총 20점을 배정한다.

- **인프라 평가점수** = Σ(확인된 시설 평가점수 × 시설 배점) ÷ Σ(확인된 시설 배점)
- **최종 추천 점수** = Σ(확인된 항목 평가점수 × 기본 가중치) ÷ Σ(확인된 항목의 기본 가중치)
- **항목별 반영점수** = 항목 평가점수 × 기본 가중치 ÷ 유효 기본 가중치 합계. 기본 가중치가 0이면 해당 항목의 기여도는 0이다. 양의 가중치 항목이 모두 유효하면 분모는 100이다.

오피스 교통 평가점수가 100점 만점에 80점이고 유효 가중치 합계가 100이면, 교통 가중치 25를 적용한 반영점수는 80 × 25 ÷ 100 = 20점이다.

근거 화면에는 항목별 기준 만점, 요청 시 계산한 평가점수, 기본 가중치, 반영점수, 확인 필요 항목을 표시한다. 기본 가중치는 매물 용도에 해당하는 `SCORE_WEIGHT.WEIGHT` 값을 사용하고, 평가점수는 11절의 평가 기준으로 산출해 Redis 캐시를 활용한다. 매물 항목별 점수를 Oracle 테이블에 별도로 저장하지 않는다.

#### 3. 거리 구간과 평가점수 기준

아래 거리 구간과 세부 배점을 적용한다. 거리형 지표는 매물 기준점에서 해당 종류의 가장 가까운 시설까지의 직선거리를 사용한다. 시설 데이터의 확인 범위 안에서 부재가 확인되면 0점을 적용한다. 데이터가 없거나 확인 범위가 불충분하면 누락 처리한다.

| 평가 대상 | 거리 구간과 평가점수 | 구간을 나눈 설계 이유 |
|---|---|---|
| 지하철역 | 500m 이하 100 · 500m 초과~1km 이하 60 · 1km 초과 20 | 도보로 역까지 접근하는 부담을 세 단계로 반영 |
| 버스정류장 | 300m 이하 100 · 300m 초과~600m 이하 60 · 600m 초과 20 | 일상적인 정류장 접근에 더 짧은 거리 기준 적용 |
| 병원·마트·주민센터·복지센터·구청·시청 | 500m 이하 100 · 500m 초과~1km 이하 80 · 1km 초과~2km 이하 60 · 2km 초과~3km 이하 40 · 3km 초과 20 | 가까운 시설의 이용 편의를 우대하고 1km 밖에서는 거리 증가에 따라 단계적으로 차등 |
| 경기장·체육관 | 200m 이하 40 · 200m 초과~500m 이하 70 · 500m 초과~1km 이하 100 · 1km 초과~2km 이하 80 · 2km 초과~3km 이하 60 · 3km 초과 20 | 500m 초과~1km를 접근성과 생활환경의 균형 구간으로 가정. 500m 이하는 근거리 소음·혼잡 가능성을 고려해 최고점 대비 30점 또는 60점 차감 |
| 학교 | 가장 가까운 초·중·고 중 한 곳까지 500m 이하 100 · 500m 초과~1km 이하 60 · 1km 초과 20 | 학교 접근성을 거리로 구분. 학교급별 비중이나 배정 학구 판단은 별도 정책으로 결정 |

교통의 내부 비중은 지하철 50·버스 50을 적용한다. 둘 다 확인되면 평균을 적용하고, 하나만 확인되면 확인된 한 수단의 평가점수를 쓴다. 경기장·체육관의 감점은 시설 평가점수 단계에서 적용한다. 해당 거리 구간은 추천 알고리즘의 평가 기준이다. 소음 항목은 같은 시설의 거리만을 근거로 근거리 감점을 중복 적용하지 않는다. 계산 예시는 다른 소음원으로 산정된 등급을 사용한다.

| 항목 | 평가점수 기준 | 적용 상태와 이유 |
|---|---|---|
| 안전 | 1km 이내 CCTV·경찰시설·소방시설 3종 확인 100 · 2종 60 · 0~1종 20 | 시설 개수보다 시설 종류의 접근성을 반영. 자료 불완전으로 구간 판정이 불가능하면 누락 |
| 소음 | 예상 등급 낮음 100 · 보통 60 · 높음 20 | 예상 노출이 낮을수록 우대. 소음원별 등급 판정 임계값은 별도 확정 대상 |
| 침수 | 낮음 100 · 보통 60 · 높음 20 | 기획서 등급표 적용. 침수 이력·예상도와 주변 대비 대지 높이를 조합 |
| 악취 | 낮음 100 · 보통 60 · 주의 20 | 기획서 판정표 적용. 건물 유형·하수처리 방식·정화조·번화가 여부 등으로 판단 |
| 가격 | 현재 모집 중 또는 모집 예정으로 노출되는 후보 중 같은 지역·용도·거래 유형의 ㎡당 가격을 비교해 하위 ⅓ 100 · 중간 ⅓ 60 · 상위 ⅓ 20 | 비교 가능한 매물 중 비용 부담이 낮을수록 우대 |
| 상권 | 같은 업종·분기의 상권별 점포당 추정매출 상위 ⅓ 100 · 중간 ⅓ 60 · 하위 ⅓ 20 | 상가에서 선택한 업종으로 비교하며 세부 가중치는 아래 기준 적용 |
| 인구 | 같은 분기의 상권별 유동인구 상위 ⅓ 100 · 중간 ⅓ 60 · 하위 ⅓ 20 | 유동인구가 많은 입지를 우대 |

#### 4. 프론트 희망 조건과 점수 연결

화면설계서의 희망 조건에서 **집은 거주 인원(1~5명 이상)**, **상가는 업종 1개(서울시 상권분석서비스 업종 코드)**, **오피스는 인원 규모와 자체 업종 분류(IT·디자인·교육·제조 등)**를 받는다. 아래 점수 연결과 배점을 적용한다. 용도별 총 가중치는 100이다.

| 프론트 입력 | 적용 항목과 가중치 | 계산 방식 |
|---|---|---|
| 상가 업종 | 상권 20 · 유동인구 15 · 업종 적합도 15 | 선택 업종의 상권 지표와 매물의 공간·설비 적합도를 평가한다. 유동인구는 해당 상권의 동일 분기 자료를 사용한다. |
| 오피스 업종 | 업종 적합도 5 | 선택 업종에 필요한 공간·설비 조건을 확인해 업종별 세부 비중으로 평가한다. |
| 집 거주 인원 | 필수 조건 | 거실을 제외한 방 수에 2를 곱해 요청 거주 인원 이상인지 확인한다. |
| 오피스 인원 규모 | 필수 조건 | 확인된 사용 가능 좌석 수를 희망 인원과 비교한다. 좌석 자료가 없으면 전용면적과 승인된 좌석 환산 기준으로 추정한다. |

##### 상가 상권 20의 세부 배점

같은 업종·분기 기준으로 상권별 **점포당 추정매출**, **전년 동기 대비 점포당 추정매출 변화율**, **업종 주요 시간대 매출 비중**을 비교한다. 각 지표의 상위·중간·하위 ⅓은 각각 100·60·20점이다. 아래 수치는 상권 20 안에서 쓰는 세부 배점이다. 유동인구 15와 업종 적합도 15는 전체 점수에서 각각 한 번 반영한다.

| 상가 업종 예시 | 점포당 추정매출 | 매출 변화율 | 주요 시간대 매출 비중 | 합계 |
|---|---:|---:|---:|---:|
| 음식점 | 12 | 5 | 3 | 20 |
| 소매 | 10 | 7 | 3 | 20 |
| 생활서비스 | 10 | 5 | 5 | 20 |

실제 화면 업종 코드와 예시 그룹의 대응표 및 업종별 주요 시간대는 확정 대상이다. 업종을 선택하지 않았거나 상권 자료가 누락된 경우 해당 지표를 확인 필요로 표시하고 유효 가중치로 재계산한다. 업종별 지역 추천의 상권 점수와 매물의 상권 항목은 같은 상권 평가점수를 사용한다.

##### 상가 업종 적합도 15의 세부 배점

희망 업종별로 공간·설비 조건 세 가지를 확인하고 각각 5를 배정한다. 조건별로 충족 100점, 부분 충족 60점, 미충족 확인 0점을 적용한다. 업종 적합도 평가점수는 확인된 조건의 가중평균으로 구한 뒤 전체 가중치 15를 적용한다. 확인 가능한 조건이 하나도 없으면 해당 평가 항목을 제외하고 유효 가중치로 재계산한다.

| 희망 업종 예시 | 조건별 세부 배점 | 합계 |
|---|---|---:|
| 음식점 | 조리 공간 5 · 급배수 5 · 배기 설비 5 | 15 |
| 소매 | 진열 공간 5 · 출입 동선 5 · 재고 보관 공간 5 | 15 |
| 생활서비스 | 서비스 공간 5 · 고객 대기 공간 5 · 업종별 필요 설비 5 | 15 |

위 업종별 조건과 공통 판정 기준을 적용한다. 해당 용도로 사용할 수 있는지도 별도로 확인하며, 사용 불가가 확인되면 해당 업종 추천 후보에서 제외한다. 사용 가능 여부가 확인되지 않으면 확인 필요로 표시한다.

##### 오피스 업종 적합도 5의 세부 배점

각 업종의 세 조건을 순서대로 평가해 충족 100점, 부분 충족 60점, 미충족 확인 0점을 적용한다. 자료 누락은 유효 세부 배점만으로 재계산한다.

| 업종 | 조건별 세부 배점 | 합계 |
|---|---|---:|
| IT | 통신 인프라 2 · 전력 설비 2 · 회의 공간 1 | 5 |
| 디자인 | 작업 공간 2 · 채광 2 · 전력 설비 1 | 5 |
| 교육 | 교육 공간 2 · 방음 2 · 방문자 접근 편의 1 | 5 |
| 제조 | 반입 동선 2 · 전력 설비 2 · 작업 공간 1 | 5 |

시설 내부 방음은 주변 환경의 소음 항목과 구별해 평가한다. 업종에 필요한 건물 용도나 사용 제한의 충족 여부는 별도로 확인한다. 사용 불가가 확인된 매물은 해당 업종 후보에서 제외하고, 확인되지 않은 매물은 확인 필요로 표시한다.

##### 집·오피스 인원 필수 조건

- **집**은 매물에 등록된 방 개수에서 거실을 제외하고, 방 1개당 최대 2명으로 계산한다. 추천 수용 인원은 `방 수 × 2`, 필요한 최소 방 수는 `요청 거주 인원 ÷ 2를 올림한 값`이다. 확인된 매물별 수용 제한이 더 낮으면 그 제한을 적용한다. 방 수를 확인할 수 없으면 확인 필요로 표시하고 추천에서 제외한다.
- **오피스**는 확인된 사용 가능 좌석이 희망 인원 이상인지 확인한다. 좌석 수를 직접 확인할 수 없으면 검증된 좌석 환산 기준이 있는 경우에만 전용면적으로 판단한다.
- **수용 미달이면 추천에서 제외**한다. 수용 가능 여부를 확인할 자료가 부족하면 확인 필요로 표시하고 추천 목록에는 포함하지 않는다. ‘5명 이상’처럼 인원 범위가 열려 있으면 정확한 인원을 받아 수용 여부를 확인한다. 사용자 인원이 입력되지 않았으면 인원을 요청한다.
- 인원 조건을 통과한 매물에만 기본 점수와 개인화 점수를 계산한다. 인원은 가중치나 AI 선호 가점에 포함하지 않는다.

#### 5. AI 채팅·검색 선호 반영 · 개인화 계산

AI 채팅과 AI 검색은 아래의 동일한 추천 알고리즘을 사용한다. AI는 요청을 검색 조건으로 변환하고, 점수는 확인된 매물 데이터와 이 문서의 계산 규칙으로 산정한다.

##### 입력부터 추천 순위까지

1. **검색 조건 해석.** 현재 채팅·검색에서 매물 용도, 거주·업무 인원, 상가·오피스 희망 업종, 지역·거래 유형·예산과 선호 항목을 추출한다. 현재 요청에서 명시한 값은 저장된 희망 조건보다 우선한다. 필수 인원이 빠졌거나 ‘5명 이상’처럼 수용 판단에 필요한 정확한 인원이 없으면 먼저 확인한다. 매물 데이터 또는 점수 기준이 없는 요청은 확인 필요로 표시한다.
2. **필수 조건 먼저 적용.** 집은 거실을 제외한 방 수 × 2명과 확인된 수용 제한을 적용한다. 오피스는 사용 가능 좌석 수 또는 4절의 확인 기준을 적용한다. 요청 인원을 수용하지 못하거나 수용 여부를 확인할 수 없는 매물은 추천 후보에서 제외한다. 상가·오피스에서 요청 업종으로 사용 불가가 확인된 매물도 제외한다. 사용자가 필수로 지정한 다른 조건은 해당 매물·거래에 적용 가능한 검색 규칙으로 확인한다.
3. **기본 점수 계산.** 통과한 매물에 집·상가·오피스별 기본 가중치 표와 2~4절 계산 기준을 적용한다. 교통·인프라·환경과 해당 용도의 학군·가격·상권·유동인구·업종 적합도 등을 계산한다. 상가의 업종별 상권 및 업종 적합도, 오피스의 업종 적합도는 선택 업종으로 계산한다. 하위 지표와 최종 항목 각각에서 누락값의 가중치를 제외하고 유효 가중치로 계산한다.
4. **개인화 가중치 계산.** 기본 가중치는 `SCORE_WEIGHT`의 용도별 고정값을 쓰고, 회원이 저장한 선호 가중치는 `MEMBER_SCORE_WEIGHT`에 용도·평가 항목별로 저장하며 항목 합계는 30으로 한다. 현재 검색에서 명시한 선호는 저장 선호보다 우선하고, 저장 선호와 결합한 검색 선호 항목은 중복을 제거해 검색 단위로 가중치 총 30에 맞춘다. 이 30점 선호 가중치를 적용하기 위해 기본 가중치를 0.7배한다. “이번에만” 지정한 선호는 DB에 저장하지 않고 현재 검색에만 적용한다. 같은 선호를 여러 번 표현해도 한 항목으로 센다. 기존 항목과 연결된 선호는 그 항목의 비중을 높이고, 난방·단열처럼 별도 기준이 있는 선호는 평가 항목을 추가한다. 인원과 필수 조건은 선호 배점에서 제외하며, 선택 업종 자체는 이미 적용한 업종 평가에 사용한다. ‘따뜻하고 조용한 집’은 소음에 15를 더해 총 24.8, 난방·단열에 15를 배정한다.
5. **누락 처리와 정렬.** 한 번의 검색 안에서는 모든 후보에 같은 기본·선호 가중치를 적용한다. 후보별 자료가 누락된 항목은 그 후보의 분자와 분모에서 해당 가중치를 함께 제외한다. 기본 항목이 누락되면 해당 70% 기본 가중치를, 개인화 항목이 누락되면 해당 선호 가중치를 제외한다. 같은 항목에 기본·선호 가중치가 모두 있으면 확인된 쪽만 포함한다. 후보마다 선호 가중치 배분을 다시 하지 않는다. 선호가 없거나 모두 확인할 수 없으면 해당 매물은 기본 점수를 사용하고, 유효 가중치가 0이면 계산 자료 부족으로 표시한다. 산출된 추천 점수의 내림차순으로 정렬하고, 표시 점수만 소수점 첫째 자리로 반올림한다.
6. **근거 표시와 선호 학습.** 평가 화면에 기본 점수, 최종 추천 점수, 적용된 선호·가중치와 확인 필요 자료를 보여준다. 현재 검색의 선호는 즉시 적용한다. 반복하거나 사용자가 저장한 선호는 다음 검색에서 불러오며, 현재 요청이 다르면 현재 요청을 우선한다. ‘이번에만’ 조건은 해당 검색에만 사용한다. 사용자는 저장된 선호를 확인·수정·삭제할 수 있다. 저장 선호 가중치 합계는 용도별 30점이 되도록 저장 시 검증한다.

##### 개인화 추천 점수 계산식

- **기본 점수** = Σ(확인된 기본 평가점수 × 기본 가중치) ÷ Σ(확인된 기본 가중치)
- **개인화 추천 점수** = (확인된 기본 가중합 × 0.7 + 확인된 선호 가중합) ÷ (확인된 기본 가중치 합계 × 0.7 + 확인된 선호 가중치 합계)

| 사용자 표현 | 반영 항목 | 매물 평가 근거 |
|---|---|---|
| 조용한 집 | 기존 소음 평가의 비중 확대 | 소음이 낮을수록 높은 평가점수 적용 |
| 따뜻한 집 | 개인화 전용 난방·단열 | 단열·창호·난방 상태 등 확인 가능한 자료를 사용한다. 100점 환산표는 별도 확정 대상이며 예시의 70점은 가상 평가점수다. |

출처는 [화면 목업 검증 대화](chatgpt-conversation://6af5786b-fb54-83ec-8fcd-a032752e6880)와 프로젝트 기획 정리 문서의 점수 가중치·침수·악취 기준이다. 별도 파일 「02_추천_점수_계산_예시」에서 입력값부터 결과까지 확인할 수 있다.

### 11.2 추천 점수 계산 예시

가상 매물에 「01_기본_점수_가중치_근거와_계산법」의 확정 기준을 적용했다. 항목별 기준 만점은 100점이고 평가점수는 가상 입력이 받은 점수다. 최종 점수도 100점 만점이며, 중간값은 그대로 계산하고 표시 점수만 소수점 첫째 자리로 반올림한다.

#### 1. 교통·인프라·학군 평가점수 만들기

교통은 지하철역 400m(100점)와 버스정류장 450m(60점)를 각각 50의 비중으로 합산한다. `(100×50 + 60×50) ÷ 100 = 80점`. 버스정류장 자료가 누락되면 교통 평가점수는 `100×50 ÷ 50 = 100점`이다.

| 인프라 시설 | 거리 | 평가점수 (100점 만점) | 배점 | 평가점수 × 배점 |
|---|---:|---:|---:|---:|
| 병원 | 400m | 100 | 20 | 2,000 |
| 마트 | 800m | 80 | 20 | 1,600 |
| 주민센터 | 1,500m | 60 | 15 | 900 |
| 복지센터 | 2,500m | 40 | 15 | 600 |
| 구청 | 3,500m | 20 | 5 | 100 |
| 시청 | 2,800m | 40 | 5 | 200 |
| 경기장 | 180m | 40 | 10 | 400 |
| 체육관 | 750m | 100 | 10 | 1,000 |
| 합계 | | | 100 | 6,800 |

인프라 평가점수는 `6,800 ÷ 100 = 68점`이다. 경기장 180m에는 적정 거리 점수 100점 대비 60점 감점이 적용돼 인프라에 4점이 반영된다. 같은 경기장이 750m였다면 평가점수 100점으로 인프라에 10점이 반영되고, 인프라 평가점수는 74점이 된다.

시청 **자료 누락** 시 인프라 평가점수는 `(6,800 − 200) ÷ (100 − 5) = 6,600 ÷ 95 ≈ 69.473684점`이다. 시청 **부재 확인** 시에는 예시의 부재 점수인 0점을 유지하므로 `6,600 ÷ 100 = 66점`이다.

학군은 가장 가까운 학교가 450m로 확인돼 평가점수 100점이다.

#### 2. 집 · 거주 인원 확인 후 점수 계산

3명이 거주할 집에는 거실을 제외한 방이 최소 2개 필요하다. 방 2개인 매물은 최대 4명으로 계산돼 인원 조건을 통과한다. 방 1개와 거실 1개인 매물은 최대 2명으로 계산돼 추천에서 제외한다. 아래 점수는 방 2개인 매물에 적용한다.

| 항목 | 가상 입력 | 기준 만점 | 평가점수 | 가중치 | 반영점수 |
|---|---|---:|---:|---:|---:|
| 교통 | 지하철 400m, 버스 450m | 100 | 80 | 18 | 14.4 |
| 인프라 | 8종 시설 확인 | 100 | 68 | 16 | 10.88 |
| 안전 | 안전시설 2종 확인 | 100 | 60 | 13 | 7.8 |
| 학군 | 학교 450m | 100 | 100 | 6 | 6 |
| 소음 | 도로 소음 보통 | 100 | 60 | 14 | 8.4 |
| 침수 | 낮음 | 100 | 100 | 11 | 11 |
| 악취 | 보통 | 100 | 60 | 6 | 3.6 |
| 가격 | ㎡당 가격 중간 ⅓ | 100 | 60 | 16 | 9.6 |
| 합계 | | | | 100 | **71.7** |

가중합 7,168을 유효 가중치 합계 100으로 나누면 71.68점이다. 화면에는 **71.7점**으로 표시한다.

소음 자료가 누락되면 소음의 가중합 840과 가중치 14를 함께 제외한다. `(7,168 − 840) ÷ (100 − 14) = 6,328 ÷ 86`을 소수점 첫째 자리로 반올림하면 **73.6점**이다. 양의 가중치가 있는 항목이 모두 누락되면 **계산 자료 부족**으로 표시한다.

#### 3. 상가 · 희망 업종이 음식점인 경우

| 항목 | 가상 입력 | 기준 만점 | 평가점수 | 가중치 | 반영점수 |
|---|---|---:|---:|---:|---:|
| 업종별 상권 | 음식점 업종의 매출·변화율·시간대 점수 100·60·100 | 100 | 90 | 20 | 18 |
| 인구 | 유동인구 상위 ⅓ | 100 | 100 | 15 | 15 |
| 업종 적합도 | 음식점: 조리 공간 충족, 급배수·배기 설비 부분 충족 | 100 | 73.33… | 15 | 11 |
| 교통 | 지하철 400m, 버스 450m | 100 | 80 | 10 | 8 |
| 가격 | ㎡당 가격 중간 ⅓ | 100 | 60 | 15 | 9 |
| 소음 | 도로 소음 보통 | 100 | 60 | 5 | 3 |
| 침수 | 낮음 | 100 | 100 | 10 | 10 |
| 악취 | 보통 | 100 | 60 | 10 | 6 |
| 합계 | | | | 100 | **80.0** |

음식점 상권 평가점수는 `(100 × 12 + 60 × 5 + 100 × 3) ÷ 20 = 90점`이다. 상권 가중치 20을 적용하면 18점이 반영된다. 업종 적합도는 `(100 × 5 + 60 × 5 + 60 × 5) ÷ 15 = 73.33…점`이고, 가중치 15를 적용하면 11점이 반영된다. 가중합 8,000 ÷ 유효 가중치 합계 100 = **80.0점**.

#### 4. 오피스 · 업무 인원 확인 후 점수 계산

8명이 사용할 오피스는 사용 가능 좌석이 8개 이상이어야 한다. 좌석 8개가 확인된 매물은 인원 조건을 통과한다. 좌석이 7개인 매물과 8명 수용 여부를 확인할 자료가 없는 매물은 추천 목록에 포함하지 않는다.

| 항목 | 가상 입력 | 기준 만점 | 평가점수 | 가중치 | 반영점수 |
|---|---|---:|---:|---:|---:|
| 교통 | 지하철 400m, 버스 450m | 100 | 80 | 25 | 20 |
| 가격 | ㎡당 가격 중간 ⅓ | 100 | 60 | 15 | 9 |
| 인프라 | 8종 시설 확인 | 100 | 68 | 10 | 6.8 |
| 업종 적합도 | IT, 통신·전력 충족, 회의 공간 미충족 확인 | 100 | 80 | 5 | 4 |
| 안전 | 안전시설 2종 확인 | 100 | 60 | 10 | 6 |
| 소음 | 도로 소음 보통 | 100 | 60 | 15 | 9 |
| 침수 | 낮음 | 100 | 100 | 10 | 10 |
| 악취 | 보통 | 100 | 60 | 10 | 6 |
| 합계 | | | | 100 | **70.8** |

IT 업종 적합도는 `(100 × 2 + 100 × 2 + 0 × 1) ÷ 5 = 80점`이다. 업종 가중치 5를 적용하면 4점이 반영된다. 가중합 7,080 ÷ 유효 가중치 합계 100 = **70.8점**.

시청 자료만 누락되면 인프라 평가점수는 `6,600 ÷ 95`로 재계산한다. 인프라 평가점수가 산출되므로 최종 유효 가중치 합계는 100이다. `(6,400 + (6,600 ÷ 95) × 10) ÷ 100`을 소수점 첫째 자리로 반올림하면 **70.9점**이다.

#### 5. AI 채팅·검색 개인화 · 따뜻하고 조용한 집

사용자가 “3명이 살 따뜻하고 조용한 집을 찾아줘”라고 하면 거주 인원 3명을 필수 조건으로 적용한다. 방 1개 매물은 점수 계산 전에 제외하고, 거실을 제외한 방 2개 매물은 점수를 계산한다. 이어서 AI는 ‘조용한’을 소음, ‘따뜻한’을 난방·단열에 연결한다. 집의 기본 평가점수는 2절과 같고, 난방·단열은 계산을 설명하기 위해 **100점 만점에 70점**으로 가정한다.

| 반영 항목 | 평가점수 | 선호에 배정한 가중치 | 선호 반영점수 |
|---|---:|---:|---:|
| 소음 (보통 등급) | 60 | 15 | 9.0 |
| 난방·단열 | 70 | 15 | 10.5 |

기본 배점 70의 반영점수는 71.68 × 0.7 = 50.176점이다. 여기에 선호 반영점수 9 + 10.5를 더하면 **개인화 추천 점수는 69.7점**이다.

나머지 조건이 같고 소음 등급만 ‘낮음’인 매물은 소음 평가점수가 60점에서 100점으로 오른다. 기본 점수에서는 5.6점 차이가 나고, 개인화 점수에서는 소음의 전체 가중치가 24.8로 커져 9.92점 차이가 난다. 이 매물의 **개인화 추천 점수는 79.6점**이다.

첫 번째 매물의 난방·단열 자료가 누락되면 해당 가중치 15도 제외한다. `(50.176 + 9) × 100 ÷ 85`을 최종 표시 자릿수로 반올림하면 **69.6점**이며, 근거에 난방·단열 확인 필요를 표시한다.

첫 번째 매물에서 난방·단열은 확인되고 기본 항목인 가격만 누락됐다면 가격의 가중합 960과 가중치 16을 제외한다. `((7,168 − 960) × 0.7 + 60 × 15 + 70 × 15) ÷ ((100 − 16) × 0.7 + 30)`으로 계산하면 **70.9점**이다.

- **DB 계정:** HOUSE_OWNER(구조 변경), WEB_APP(Web 접속), DATA_APP(Data 접속, 회원 정보 접근 불가), AI_APP(AI 접속, 문서 벡터 테이블만 접근, 회원 정보 접근 불가)
- **DB 변경:** Git의 SQL 파일로 관리
- **관리자 계정:** 관리자 계정을 따로 만들지 않고 회원가입한 회원에게 관리자 권한을 부여합니다. 슈퍼 관리자는 회원가입 없이 배포 때 DB에 직접 넣습니다(회원 1명 + SUPER_ADMIN 권한, 아이디·비밀번호는 환경 변수로 받아 BCrypt 저장, 저장소에 비밀번호 없음). 일반 관리자는 일반 회원처럼 가입한 뒤 가입 아이디를 슈퍼 관리자에게 알려 주고, 슈퍼 관리자가 회원 관리 화면에서 아이디를 검색해 역할(SUPER_ADMIN·ADMIN)을 선택해 승급합니다(별도 운영자 이름 입력·저장 없음). 관리자 표시는 MEMBER.NICKNAME을 사용하며 ADMIN.ADMIN_ID는 MEMBER.MEMBER_ID와 같은 회원 ID입니다(별도 운영자 추가·권한 요청·관리자 가입 화면 없음). 회원 관리는 일반 관리자도 들어갈 수 있지만 회원 조회(개인정보 가림)와 이용 정지·해제(사유 입력)만 하고, 승급·역할 변경·권한 회수는 슈퍼 관리자만 할 수 있습니다(화면에서 숨기고 서버에서도 차단). 모든 처리는 대상 계정·처리자·시각을 처리 이력에 남깁니다(초대 메일·초기 비밀번호 없음, 삭제 대신 권한 회수). 일반·소셜 가입 모두 아이디·비밀번호를 설정하므로 같은 승급 기준을 적용하며, 권한이 있는 회원은 권한을 먼저 회수해야 탈퇴할 수 있습니다. 관리자도 일반 로그인 화면으로 로그인하고 관리자 권한이 있으면 관리자 화면에 들어가며(권한이 없으면 403), 로그인 5회 실패 잠금·접속 기록을 적용하고 자기 자신과 마지막 슈퍼 관리자의 권한은 회수할 수 없습니다.
- **보안:** 입력 정보 AES-256 암호화, 비밀번호 BCrypt, HTTPS, CSRF 방어, 요청 수 제한, 로그인 5회 실패 잠금. OpenAI에는 식별 정보와 소득·자산·가족 정보 전송 금지(추천 사유에 필요한 희망 조건만 전송). OpenAI 처리 위탁·국외 이전 사실은 개인정보처리방침에 고지합니다. API 키는 환경변수와 GitHub Secrets에 보관
- **첨부파일:** 1:1 문의 첨부(JPG·JPEG·PNG·PDF, 파일당 5MB, 최대 3개)는 DB가 아닌 파일 저장소에 무작위 이름(UUID)으로 저장하고 DB에는 경로·원본 파일명·용량만 저장. 서버에서도 형식·용량·개수 검증, 답변 완료 1년 후 자동 삭제

- **중복 정리:** 건물 정보(층·준공일·면적)는 건축물대장을 실시간으로 불러와 기준으로 삼고, 실거래·공매 값은 해당 거래·물건 정보로만 사용. 공공 상가 공고와 온비드 물건이 겹치면 수집 때 주소·공고 기관으로 비교하고, 저장된 뒤에는 좌표로 중복 제거. 온비드 소재지 주소로 PNU·좌표를 찾아 건물·위치 정보와 연결
- **브이월드 용도별건물:** 건축물대장·GIS 건물통합정보와 용도 정보가 겹쳐서 데이터 수집에는 쓰지 않음(필요하면 지도 용도 표시용 WMS만 사용)
- **네이버 지도:** 결과 데이터는 저장하지 않고 표시·거리뷰·길찾기 연결에만 사용합니다. 좌표는 공공 데이터로 만들어 저장합니다.
- **홍수위험지도:** 공공누리 4유형이라 등급 계산에 사용하지 않습니다.

## 16. 남은 과제

- **데이터 확인:** 온비드 용도 분류 코드와 응답 필드, 건축HUB 전유부·전유공용면적 필드와 변경된 건축데이터 PK, 건물별 일조 데이터, 소음원 위치 데이터, 좌표 변환과 저장 조건, 침수 파일 형식, 합류식·분류식 위치 자료, 학구도, SH 공고 API, 서울 공고 수, 토지특성 지형높이 코드표와 서울 필지 실제 값, 사무실 임대 데이터 공개 범위
- **기준 검증·세부 확정:** 가격·상권 비교 집단과 최소 표본 수, 비교 기준 분기·이상치 처리, 소음 거리 구간, 정화조 용량, 번화가 판정, 침수 단계와 인접 거리, 대지 높이 기준
- **ERD:** `프로젝트 구상/ERD`(테이블 49개, 기준 SQL: `ERD/final.sql`, 2026-11-18). 공고·공매·건물은 목록·지도·필터·자격 판단에 필요한 최소 정보와 관리자 승인값만 저장하고, 상세에서 쓰는 실시간 정보는 API 호출과 Redis 캐시로 처리한다. 회원의 집·상가·오피스 희망 조건은 SEARCH_PREFERENCE와 유형별 HOUSE_PREFERENCE·STORE_PREFERENCE·OFFICE_PREFERENCE에 나눠 저장한다. 주변 환경 요약은 PLACE_ENV에 저장하며, 매물 항목별 평가점수와 최종 추천 점수는 Oracle에 저장하지 않고 요청 시 계산해 Redis 캐시를 활용한다. SCORE_WEIGHT에는 용도별 기본 가중치, MEMBER_SCORE_WEIGHT에는 회원이 저장한 선호 가중치를 보관한다.
- **팀 결정:** 평가 필수 기술, 공매 데이터 수집 담당
