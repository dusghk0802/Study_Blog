# SpaceLink 기획안 (서울 맞춤 주택·상가·오피스 추천 서비스)

> 노션 통합 기획안 + 화면설계서(화면 33개) 기준. 최종 수정 2026-11-13

## 1. 서비스

SpaceLink는 사용자 조건을 분석해 서울의 청약 공고와 조건에 맞는 집·상가·사무실을 추천하고, 판단 근거와 주변 환경 정보를 함께 보여 주는 포트폴리오 서비스입니다.

- **1순위:** 아파트, 오피스텔, 도시형생활주택, 민간임대, 무순위·잔여세대, 공공분양·공공임대 공고
- **2순위:** 조건에 맞는 일반 건물(집) 분석. 매매·전월세 실거래와 건물 정보를 바탕으로 추천함. 일반 건물은 분석 정보일 뿐 매물이 아니므로 신청 버튼을 두지 않음(주택 매물 데이터는 청약 공고만)
- **상가:** 공공 상가 공고 + 업종별 입지·건물 분석. 매물 데이터는 공매 물건만 다루고, 신청 버튼은 공공 공고(공급기관 공식 신청 페이지)와 공매(온비드 입찰 페이지)에만 둠
- **사무실(오피스):** 업무시설 입지·건물 분석. 주거용 오피스텔과 구분. 매물 데이터는 공매 물건만 다루고, 신청 버튼은 공공 공고와 공매에만 둠
- **공매:** 온비드 공매 물건(서울)을 집·상가·오피스 목록에 건물 분석 결과와 함께 표시하고 "공매" 라벨로 구분. 별도 공매 화면은 두지 않음
- **사용자:** 청년, 신혼부부, 유자녀 가족, 노부부, 독거노인, 자영업자, 프리랜서
- **서비스 역할:** 예상 자격, 예상 가점, 맞춤 추천, 판단 근거 제공. 청약 신청 대행, 공매 입찰 대행·권리 분석, 공식 자격 확정, 수익·창업 성공 예측, 매물 중개·계약은 하지 않음
- **개발 기간:** 2026-11-18 ~ 2026-12-18 (2인 팀)

## 4. 기능

| 기능 | 내용 |
| --- | --- |
| 회원가입·로그인 | 아이디·비밀번호 가입과 구글·네이버·카카오 로그인, 약관 동의(필수·선택, 동의 일시·버전 저장. 약관을 고치면 새 버전으로 추가하고 가입 화면은 시행 중인 최신 버전 표시, 선택 동의 철회도 새 기록으로 남김), 이메일 인증, 생년월일(캘린더·직접 입력, 만 14세 미만 불가), 이메일 수신 동의(내외국인은 맞춤 청약 조건에서 입력). 5회 실패 시 잠금, 비밀번호 BCrypt 저장 |
| 아이디·비밀번호 찾기 | 아이디는 가입 이메일로 안내 메일(템플릿) 발송. 비밀번호는 보내지 않고 재설정 링크(30분·1회용) 발송. 가입 여부가 드러나지 않게 같은 안내 문구 사용 |
| 맞춤 청약 조건 | 맞춤 청약 첫 이용 때 6개 섹션 입력(기본·거주, 혼인·가족·세대, 주택 소유, 청약통장, 당첨 이력, 소득·자산). 임시 저장 가능, 마이페이지에서 수정·삭제 |
| 찾는 대상·희망 조건 | 맞춤 추천·상가·오피스 첫 이용 때 입력. 사용자 유형은 앞 단계에서 한 번 선택(기본 선택과 가중치에 사용). 찾는 대상은 드롭다운에서 집·상가·오피스 중 하나를 고르면 그 대상의 조건이 아래에 표시되고 대상별로 따로 저장. 조건을 저장한 대상이 찾는 대상 |
| 맞춤 추천 | 찾는 대상별 공고 목록(자격 판단, 예상 가점)과 건물 목록(가격, 입지, 침수, 악취), 슬라이더로 가중치 조정, AI 추천 사유 |
| 지도 | 공공 데이터 좌표를 저장해 네이버 지도에 핀 표시(상태별 색상, 클러스터). 청약 목록 지도는 기존 SUB_LIST-01에서 제공하고, 통합 매물 지도는 PROP_MAP-01에서 제공 |
| 매물 지도 | 집·상가·오피스 매물(공매 포함)과 현재 모집 중인 청약·공공 공고를 한 지도에 핀으로 표시한다. 유형별 필터, 지도 이동에 따른 범위 검색, 마커 클러스터를 제공하고 핀을 누르면 해당 상세 화면으로 이동한다. |
| 메인 홈 | 빠른 검색(지역·유형·접수 상태), 하이브리드 AI 검색·추천, 매물 Top 5(조회수 기준 접수 중 매물 상위 5개를 아래에서 위로 한 개씩 롤링), 알고리즘 추천 카드 5~6개(3개씩, 이전·다음), 바로가기·공지 |
| 청약 | 목록 + 지도, 메인 홈 일정 캘린더, 내 조건 기준 보기, 공고 상세(기본정보, 모집 일정, 예상 자격·가점, 가격·면적, 주변 환경, 준비서류 안내(공고문 제출서류를 텍스트로 표시), 공식 원문) |
| 집 | 매매·전월세 실거래 기반 건물 목록, 희망 조건 기준 추천 점수. 주거용 공매 물건 함께 표시. 상세는 건물 상세 공통 구성 참조. 일반 건물은 매물이 아니므로 신청 버튼이 없고, 공매 물건만 온비드 입찰 페이지로 이동 |
| 상가 | 전체 / 공공 상가 공고 / 일반 건물 분석 / 공매 구분(전체에서 건물 분석 결과·공공 공고·공매 함께 표시), 업종별 지역 추천(상권 점수). 상세는 건물 상세 공통 구성 참조. 공공 공고는 공급기관 공식 신청 페이지로, 공매는 온비드 입찰 페이지로 이동하는 버튼을 제공 |
| 오피스 | 전체 / 공공 오피스 공고 / 일반 건물 분석 / 공매 구분(전체에서 건물 분석 결과·공공 공고·공매 함께 표시), 입지 점수. 상세는 건물 상세 공통 구성 참조. 공공 공고는 공급기관 공식 신청 페이지로, 공매는 온비드 입찰 페이지로 이동하는 버튼을 제공 |
| 건물 상세(집·상가·오피스 공통) | 집·상가·오피스 상세는 같은 구성으로 표시하고, 대상에 없는 값은 빼지 않고 ‘해당 없음’ 또는 ‘확인 필요’로 표시. ① 기본 정보: 건물 용도·용도지역·위치·연면적·층수·준공일·엘리베이터, 호실 정보(동·호, 전용·공용면적, 층, 구조) ② 가격: 매매·전월세 실거래 추이 그래프, 평당가, 보증금·임대료(지역 평균 임대 시세) ③ 추천 점수와 항목별 근거 ④ 주변 환경: 교통(지하철역·거리·환승 노선 수, 버스 정류장), 생활 편의시설, 침수 등급, 소음 등급(주요 원인), 악취 판정, 주차, 같은 업종 수, ‘3D 주변 환경·일조량 보기’ 팝업, 출처·기준일 ⑤ 공매 물건이면 회차별 입찰 정보·누적 유찰·입찰 제한·지분 여부, 온비드 공고 링크 ⑥ 신청 페이지: 공공 공고는 공급기관 공식 신청 페이지, 공매는 온비드 입찰 페이지로 이동하는 버튼 제공(일반 건물은 매물이 아니므로 버튼 없음). 신청 URL이 없거나 신청 기간이 아니면 신청 상태와 경로를 안내하며, SpaceLink 자체에서 신청·중개·계약을 처리하지 않음 |
| 공매 | 온비드 서울 물건만. 주거용(아파트·연립·다세대·다가구·단독·주거용 오피스텔)은 집, 상업용(근린생활시설·숙박시설·백화점·쇼핑센터)은 상가, 업무·산업용(오피스빌딩·지식산업센터)은 오피스 목록에 "공매" 라벨로 표시. 카드에 감정가·최저입찰가·입찰 기간, 상세에 회차별 입찰 정보·누적 유찰·입찰 제한, 온비드 공고 링크 |
| 주변 환경 | 건물 상세·공고 상세 공통 표시. 교통(지하철역·거리·환승·버스 정류장), 생활 편의시설, 침수 등급, 소음 등급(주요 원인), 악취 판정, 주차, 같은 업종 수, 출처·기준일. ‘3D 주변 환경·일조량 보기’ 버튼을 누르면 레이어 팝업으로 3D 주변 건물과 사계절 일조량 표시 |
| 청약 자격 | 가능성 있음 / 확인 필요 / 해당 없음. 공통 규칙은 관리자 등록, 공고별 조건은 AI 초안 후 관리자 승인. 승인 전 공고도 공개하되 자격은 확인 필요 |
| 찜·후보 비교 | 찜 개수 제한 없음. 같은 종류 후보 3개 정도를 표로 비교하고 맨 아래에 AI 추천 이유 표시 |
| 알림 | 새 추천 공고, 찜 공고 접수 시작·마감 D-1, 당첨 발표, 정정 공고, 문의 답변. 사이트 내 알림(SSE)과 이메일 |
| 고객센터 | 공지사항, FAQ, AI 고객상담(웹사이트 이용 문의만), 1:1 문의(첨부 JPG·JPEG·PNG·PDF, 파일당 5MB, 최대 3개) |
| 안내 | 서비스 이용 안내, 청약 제도 안내(1순위 요건, 가점, 특별공급, 용어 사전), 데이터 출처·약관(데이터 출처는 DB 없이 고정 페이지로 관리하고, 각 화면의 출처 문구도 화면에 고정. DB에는 데이터별 기준일만 저장) |
| 관리자 | 대시보드(수집 현황, 승인 대기, 수집 오류, 좌표 확인, 미답변 문의, 알림 실패), 공고 조건 승인, 자격 규칙·가점표, 문의 답변, 상가·오피스·공매 데이터 관리, 알림 발송 관리, 공지·FAQ 관리, 처리 이력, 운영자 관리 |

| 집 | 거래 유형(매매·전세·월세 복수 선택), 거래 유형별 예산 구간(매매가, 전세 보증금, 월세 보증금·월세), 거주 인원 |
| 상가 | 업종(1개), 보증금 구간, 임대료 구간 |
| 오피스 | 인원 규모, 업종, 보증금 구간, 임대료 구간 |

- 생년월일은 가입 때 받고, 내외국인은 맞춤 청약 조건(기본·거주)에서 받습니다. 둘 다 마이페이지 계정에서 수정합니다. 나머지는 해당 기능 첫 이용 때 입력하고 마이페이지에서 수정·삭제합니다.
- 주민등록번호, 외국인등록번호, 청약통장 번호, 증빙서류는 받지 않습니다. 금액은 구간으로만 받고 AES-256으로 암호화 저장합니다.
- 청약 프로필은 세세한 입력 없이 라디오 버튼·체크박스·구간 선택만으로 받고, 예라고 답한 항목에만 세부 선택지를 보여 줍니다. 미입력 항목은 판정하지 않고 ‘확인 필요’로 표시합니다. 만 나이, 무주택 기간(한 번도 없음일 때), 인정 부양가족 수는 예상값으로 표시합니다. 구간 경계는 주요 공고 기준 금액·기간에 맞춰 공통코드로 관리하고, 선택한 구간이 공고 기준선에 걸치면 ‘확인 필요’로 표시합니다.
- 자동차가 있으면 차량 기준가액 합계 구간을 반드시 선택합니다(‘모름’ 없음). 합계 구간 전체가 기준 이하면 통과, 초과면 미달, 기준선에 걸치거나 공고가 합산이 아닌 다른 계산 방식이면 ‘확인 필요’로 표시합니다.
- 생년월일·내외국인·청약 프로필·희망 조건을 바꾸면 예상 자격과 추천을 다시 계산합니다.
- 찾는 대상은 드롭다운에서 집·상가·오피스 중 하나를 고르면 그 대상의 조건 칸이 아래에 표시되고, 회원당 한 행 안에 대상별 칸으로 나눠 저장합니다(한 대상을 저장해도 다른 대상 조건은 그대로 남음). 조건을 저장한 대상이 찾는 대상이며 모두 추천에 쓰입니다. 집은 거래 유형 중 하나라도 선택했으면, 상가는 업종이, 오피스는 인원 규모가 있으면 저장한 것으로 보고, 대상 조건을 삭제하면 그 대상 칸을 비웁니다. 희망 지역은 받지 않고 서울 전체를 대상으로 합니다.
- 보유 주택은 주소를 받지 않고 공시가격 합계 구간만 받습니다. 사용자가 부동산 공시가격 알리미 등에서 확인해 고르도록 안내합니다.
- 테이블은 MEMBER, SUBSCRIPTION_PROFILE(청약 프로필, 선택값을 한 행에 저장), SEARCH_PREFERENCE(찾는 대상·희망 조건)로 나눕니다(이름은 초안).

## 7. 메인 홈 AI 검색·추천과 맞춤 배너

- **하이브리드 검색:** 필터(지역·유형·접수 상태)는 빠른 검색으로 청약 목록에 이동하고, 문장 질문은 AI 검색·추천으로 처리합니다. 예: "성동구 신혼부부가 넣을 만한 공고", "아이 키우기 좋은 조용한 동네"
- **흐름:** 질문(개인정보 마스킹) → OpenAI가 조건으로 변환 → Tool Calling → PKG_RECOMMEND가 후보와 순위 계산 → SSE로 답변과 추천 카드를 홈에 표시. 답변 중지와 추가 질문 가능
- **대화 저장 안 함:** AI 검색·추천과 AI 고객상담 대화는 DB에 저장하지 않습니다. 페이지에 있는 동안만 화면이 대화를 기억해 질문할 때 함께 보내고, 페이지를 벗어나면 초기화합니다. 마음에 드는 카드는 찜으로 남깁니다. AI 고객상담 → 1:1 문의 전환은 그 자리에서 요약을 문의 작성 화면으로 넘깁니다
- **Tool Calling:** searchListings(공고·집·상가·오피스 검색), searchNoticeDocs(공고문 RAG), checkEligibility(자격 판단 결과와 근거), getSchedule(접수·마감 일정). Tool은 조회만 하고, 카드는 Tool이 돌려준 ID로 Web이 만듭니다
- **AI 역할 제한:** OpenAI는 조건 변환, Tool 선택, 추천 이유 작성만 맡습니다. 회원 식별은 요청 토큰으로 처리해 모델에 보내지 않고, 소득·자산·가족 정보는 보내지 않습니다
- **고객센터 AI 고객상담과는 별개입니다.** AI 고객상담은 계정·로그인, 알림, 오류, 탈퇴, 데이터 출처 등 웹사이트 이용 문의만 답하고, 공고·청약 자격 질문은 청약 목록·공고 상세로 안내합니다

학습은 모델 학습이 아니라 사용자 행동을 DB에 기록해 점수에 반영하는 방식입니다. 아래 수치는 모두 시작값입니다.

| 행동 | 점수 |
| --- | --- |
| 카드 클릭 | +1 |
| AI 검색·조건 검색 | +2 |
| 상세 조회 | +3 |
| 관심 등록 | +5 |
| 관심 없음 표시 | -5 |

- **집계:** 지역, 주택 유형, 거래 유형, 가격대별로 쌓고, 30일이 지나면 점수를 절반으로 줄입니다.
- **보관:** 원본 기록은 90일만 보관하고, 탈퇴하면 삭제합니다. 행동 기록 수집은 약관 동의에 추가합니다(질문 원문은 저장하지 않음).
- **배너 점수:** 기본 추천 점수 × (1 - a) + 행동 선호 점수 × a. 행동 기록이 5건 미만이면 a는 0, 5~29건이면 0.15, 30건 이상이면 0.3입니다.
- **카드 구성:** 자격이 해당 없음이거나 마감된 공고는 제외하고, 공고·건물·상가 칸을 나눕니다. 카드마다 추천 이유를 표시합니다. 메인 홈 알고리즘 추천은 카드 5~6개를 3개씩 보여 주고 이전·다음 버튼으로 넘깁니다.
- **추천 정렬:** 자격 가능성(신청 자격이 될 것 같은 공고 먼저) → 개인 취향(찜·클릭 등 행동 기록으로 계산한 맞춤 배너 점수, 기록이 없으면 이 단계는 건너뜀) → 현재 거주지와 가까운 공고 순. 비로그인은 최신·마감 임박 공고로 채웁니다.
- **구현:** USER_EVENT, USER_BANNER_CARD 테이블을 쓰고, 하루 1회 배치로 계산합니다. 행동 선호 점수는 따로 저장하지 않고 배치에서 USER_EVENT를 바로 집계합니다. 회원 정보와 연결되므로 WEB_APP 계정으로 실행합니다.

## 8. 알림과 이메일

- **흐름:** Data가 새 공고를 저장하면 Web 스케줄러가 회원 조건과 매칭해 NOTIFICATION에 저장하고, 채널별로 처리합니다.
- **사이트 내 알림(이연화):** SSE로 전송합니다. DB에 먼저 저장하고, 재연결 때 놓친 알림을 다시 보냅니다. 헤더에 안 읽은 알림 수 표시
- **이메일(정려립):** NOTIFICATION에서 대상을 읽어 발송하고 결과를 기록합니다. 맞춤 알림 수신 동의 회원만 대상입니다.
- **추천 공고 메일:** 새 추천이 있을 때만 보내고(없으면 발송하지 않음), 한 메일에 최대 5건을 요약 + 링크로 보냅니다. 이미 보낸 공고는 다시 보내지 않습니다. 필요하면 관련 안내 문서를 Google Docs로 첨부하고, 공고 원문 파일은 링크로 안내합니다.
- **따로 보내는 메일:** 정정 공고, 찜 공고 마감 D-1, 문의 답변, 아이디 안내·비밀번호 재설정 링크(템플릿)
- **메일 원칙:** 소득·자산 등 판정 근거는 넣지 않고, 하단에 알림 설정·수신 거부 링크를 넣습니다.
- **중복 방지:** 회원, 알림 유형, 대상의 조합에 유니크 제약을 겁니다.

## 9. 공고 조건 승인과 공고문 처리

- **흐름:** AI가 공고문에서 조건 초안을 만들면 승인 대기로 저장하고, 관리자가 원문·AI 추출값·최종값을 대조해 승인한 조건만 자격 판단에 씁니다.
- **관리자 화면:** 대기 목록, AI 초안과 공고문 링크, 수정 입력칸, 승인·반려(사유 필수) 버튼. 비정상 값이나 빈 필수 항목은 자동 강조
- **승인 전:** 공고는 사이트에 보여 주고, 자격 판단은 ‘확인 필요’로 표시합니다. 정정 공고가 수집되면 다시 ‘확인 필요’로 돌립니다.
- **담당:** 정려립은 관리자 화면, 팀장은 조건 추출과 자동 검사, 자격 판단을 맡습니다.
- **합의 필요(초안):** 조건 테이블(공고 ID, 항목, AI 추출값, 최종값, 원문 위치), 상태 값(대기, 승인, 반려)
- **첨부파일 범위:** 주택(청약·공공 임대)·상가·오피스 공고와 온비드 공매의 공고문과 첨부파일(호실·주택형 표, 감정평가서 등)을 모두 수집해 공고문·첨부 파일 테이블에 저장합니다(PDF, HWP, HWPX, XLSX, 스캔). 청약 공고는 자격 조건(소득·자산·자동차·무주택·거주·청약통장)을, 상가·오피스 공고는 입점·입주 자격, 업종 제한, 임대 기간, 보증금·임대료 조건, 호실별 조건과 호실 목록(공급 단위)을, 공매는 입찰 제한·제출 서류·지분·권리 관계 안내를 추출하며, 모두 관리자가 확인한 값만 화면에 표시합니다.
- **공고문 처리:** Data가 공고문 파일을 수집하고, 자격 표 페이지를 찾아 300dpi 이미지로 자른 뒤, AI가 Spring AI와 gpt-5.4-mini로 조건 초안을 만들고, 관리자가 승인하면 Web의 Java 규칙이 자격을 판단합니다.
- **파일 범위:** PDF 민영·공공분양 공고부터 처리하고, 아래한글과 스캔본은 그다음에 붙입니다. 항목마다 AI 추출값과 원문 위치를 저장합니다. 공고문의 제출서류 부분도 같은 단계에서 텍스트로 뽑아 공고에 저장하고, 관리자가 조건과 함께 확인합니다.
- **RAG:** 공고문은 조각내어 문서 벡터 테이블에 저장하고, 자격 판단과 점수에는 쓰지 않습니다.
- **Python:** 페이지 이미지 생성과 자르기는 PDFBox(Java)로 처리하고, 이 방식으로 안 될 때만 Python을 씁니다.
- **검증:** 공공분양 3건은 시험했고, 표 자동 자르기와 민영·아래한글·스캔본이 남았습니다.

## 10. 찜과 후보 비교

- **찜:** 추천 카드와 각 목록·상세에 버튼을 두고, 행동 점수의 관심 등록에 반영합니다. 개수 제한은 없습니다. 찜 목록은 마이페이지 안에 두고 정려립이, 찜한 공고의 접수·마감 알림은 이연화가 맡습니다.
- **후보 비교(이연화):** 찜 목록과 각 목록의 ‘비교 담기’에서 사용자가 직접 고른 3개 정도를 같은 종류끼리 공통 템플릿 표로 비교합니다. 항목별 가장 좋은 값과 희망 조건과 다른 값을 강조합니다.
- **AI 추천 이유:** 표 맨 아래에 SSE로 표시합니다. 후보 정보, 예산·거래 유형·업종·인원 등 희망 조건, 사용자 유형, 자격 판단 결과만 보내고, 이름·연락처·이메일·회원 ID·생년월일·소득·자산·가족·청약통장·당첨 이력은 보내지 않습니다. OpenAI 처리 위탁·국외 이전 사실은 개인정보처리방침에 고지합니다.
- **비교 항목:** 청약(공급 유형, 분양가, 예상 자격, 가점, 일정, 입지 점수), 집(거래가, 평당가, 면적, 교통, 침수, 악취, 엘리베이터), 상가·오피스(임대료·매매가, 면적, 층, 상권·입지 점수, 경쟁 업체)

- **관리자 계정:** 관리자 계정을 따로 만들지 않고, 아이디로 가입한 회원에게 관리자 권한을 부여합니다. 최초 슈퍼 관리자는 배포 시 시드 SQL로 회원 1명을 만들고 SUPER_ADMIN 권한을 줍니다(초기 비밀번호는 환경 변수로 받아 BCrypt 저장, 첫 로그인 때 변경 강제). 이후 슈퍼 관리자가 운영자 관리 화면에서 가입된 회원의 아이디를 검색해 역할(SUPER_ADMIN·ADMIN)을 부여·변경·회수하고, 대상 계정·승인자·시각을 처리 이력에 남깁니다(초대 메일·초기 비밀번호 없음, 삭제 대신 권한 회수). 소셜 로그인 회원은 비밀번호가 없어 권한을 받을 수 없고, 권한이 있는 회원은 권한을 먼저 회수해야 탈퇴할 수 있습니다. 관리자 화면은 별도 로그인 주소를 유지하고 로그인 5회 실패 잠금·접속 기록을 적용하며, 자기 자신과 마지막 슈퍼 관리자의 권한은 회수할 수 없습니다.
- **보안:** 입력 정보 AES-256 암호화, 비밀번호 BCrypt, HTTPS, CSRF 방어, 요청 수 제한, 로그인 5회 실패 잠금. OpenAI에는 식별 정보와 소득·자산·가족 정보 전송 금지(추천 사유에 필요한 희망 조건만 전송). OpenAI 처리 위탁·국외 이전 사실은 개인정보처리방침에 고지합니다. API 키는 환경변수와 GitHub Secrets에 보관
- **첨부파일:** 1:1 문의 첨부(JPG·JPEG·PNG·PDF, 파일당 5MB, 최대 3개)는 DB가 아닌 파일 저장소에 무작위 이름(UUID)으로 저장하고 DB에는 경로·원본 파일명·용량만 저장. 서버에서도 형식·용량·개수 검증, 답변 완료 1년 후 자동 삭제

## 16. 남은 과제

- **데이터 확인:** 온비드 용도 분류 코드와 응답 필드, 건축HUB 전유부·전유공용면적 필드와 변경된 건축데이터 PK, 건물별 일조 데이터, 소음원 위치 데이터, 좌표 변환과 저장 조건, 침수 파일 형식, 합류식·분류식 위치 자료, 학구도, SH 공고 API, 서울 공고 수, 토지특성 지형높이 코드표와 서울 필지 실제 값, 사무실 임대 데이터 공개 범위
- **기준 확정:** 금액 구간, 점수와 가중치, 소음 거리 구간, 정화조 용량, 번화가 판정, 침수 단계와 인접 거리, 대지 높이 기준
- **ERD:** `프로젝트 구상/ERD`(테이블 50개). 건물 호실과 공매 회차별 입찰 정보는 테이블 없이 실시간 호출 + Redis 캐시로 처리
- **팀 결정:** 평가 필수 기술, 공매 데이터 수집 담당
