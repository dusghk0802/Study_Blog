#### 1. CINEHUB 미니 프로젝트 발표

지금까지 팀 프로젝트로 진행한 CINEHUB의 기획 내용과 구현 결과를 발표하였다.

CINEHUB는 영화 정보 조회, AI 기반 영화 추천, 커뮤니티 기능을 하나의 서비스에서 이용할 수 있도록 구성한 영화 추천 및 커뮤니티 웹 서비스이다.

발표에서는 프로젝트의 전체적인 구조와 주요 기능을 설명하고, 화면설계서를 기반으로 실제 서비스에서 각 화면이 어떤 역할을 하는지 설명하였다.

주요 기능은 다음과 같다.

* 영화 검색 및 AI 영화 추천
* 영화 상세정보 및 한줄평
* 32강 영화 밸런스 게임
* 사용자 취향 기반 영화 추천
* 게시판 및 댓글
* 좋아요 및 신고
* 댓글 알림
* 회원 및 관리자 기능
* 관리자 로그 관리

#### 2. 화면설계서를 활용한 기능 설명

발표에서는 화면설계서에 작성한 번호를 기준으로 각 화면의 기능을 순서대로 설명하였다.

메인 화면에서는 주요 메뉴와 인기 영화, 인기 게시글을 설명하였고, 회원가입과 로그인 화면에서는 사용자 정보를 검증하고 로그인 상태를 관리하는 과정을 설명하였다.

영화 추천 화면에서는 사용자가 입력한 조건을 기반으로 영화를 추천하는 기능을 설명했으며, 영화 상세 화면에서는 영화정보 조회와 한줄평 등록 및 좋아요 기능을 설명하였다.

또한 밸런스 게임과 취향 추천 기능을 통해 사용자의 선택을 기반으로 영화를 추천하는 과정을 설명하였다.

커뮤니티에서는 게시글 목록, 게시글 상세, 게시글 작성, 댓글, 좋아요, 신고 및 알림 기능의 동작 과정을 설명하였다.

관리자 화면에서는 회원 제재, 게시글 관리, 신고 처리와 관리자 작업 및 로그인 기록을 확인하는 기능을 설명하였다.

#### 3. 영화 추천 기능의 구조 이해

프로젝트의 영화 추천 기능은 단순히 영화 제목을 검색하는 방식뿐만 아니라 사용자가 자연어로 입력한 내용을 기반으로 영화를 추천할 수 있도록 구성하였다.

```text
사용자 자연어 입력
        ↓
Oracle DB 키워드 검색
        +
Qdrant 시맨틱 검색
        ↓
추천 후보 영화 생성
        ↓
OpenAI
        ↓
최종 영화 선택 및 추천 이유 생성
```

Oracle DB에서는 제목이나 줄거리 등의 키워드를 기반으로 후보 영화를 찾고, Qdrant에서는 영화 줄거리의 의미적인 유사도를 기반으로 관련 영화를 검색한다.

이렇게 만들어진 후보를 기반으로 OpenAI가 최종 추천 영화를 선택하고 사용자에게 추천 이유를 제공한다.

이를 통해 AI가 존재하지 않는 영화를 임의로 생성하도록 하는 것이 아니라, 실제 영화 데이터를 기반으로 추천하도록 구성할 수 있다는 점을 알게 되었다.

#### 4. 세션 기반 로그인 구조 이해

발표 예상 질문을 정리하면서 프로젝트의 로그인 및 세션 처리 방식도 다시 확인하였다.

사용자가 로그인을 완료하면 서버에서 세션 토큰을 생성하고 브라우저의 쿠키에 저장한다.

```text
아이디·비밀번호 입력
        ↓
서버에서 회원정보 확인
        ↓
로그인 성공
        ↓
세션 토큰 생성
        ↓
브라우저 쿠키 저장
        ↓
이후 요청마다 세션 확인
```

서버에서는 세션 토큰과 사용자 정보를 연결하여 관리하고, 요청이 들어올 때마다 쿠키의 세션 정보를 확인하여 로그인된 사용자인지 판단한다.

또한 관리자 기능은 로그인 여부뿐만 아니라 사용자의 역할이 `ADMIN`인지 추가로 확인하여 접근 권한을 구분한다.

#### 5. 웹 서비스 보안 방식 이해

예상 질문을 준비하면서 웹 서비스에서 사용하는 기본적인 보안 방식에 대해서도 정리하였다.

비밀번호는 원본 값을 그대로 DB에 저장하지 않고 해시값으로 변환하여 저장한다.

SQL 실행 시에는 `PreparedStatement`를 사용하여 사용자의 입력값이 SQL 명령어로 처리되는 SQL Injection 문제를 방지할 수 있다.

또한 화면에서 사용자 입력값을 출력할 때 JavaScript 코드가 실행되지 않도록 처리하여 XSS 공격을 방지하고, 데이터 변경 요청에는 별도의 CSRF 토큰을 확인하여 사용자의 의도와 관계없이 요청이 실행되는 것을 방지한다.

```text
비밀번호 → 해시 처리

SQL Injection → PreparedStatement 사용

XSS → 사용자 입력값 이스케이프 처리

CSRF → CSRF 토큰 검증
```

각 보안 기술의 이름만 알고 있었던 것보다 프로젝트에서 어떤 부분을 보호하기 위해 사용되는지를 함께 이해하는 것이 중요하다는 것을 알게 되었다.

#### 6. 데이터베이스와 서비스 기능의 연결

프로젝트 발표를 통해 화면에 표시되는 하나의 기능도 여러 데이터베이스 테이블과 연결되어 있다는 것을 확인하였다.

예를 들어 게시글 조회수는 단순히 숫자를 증가시키는 것이 아니라 사용자별 조회 기록을 저장하여 같은 사용자가 동일한 게시글을 여러 번 조회하더라도 조회수가 중복으로 증가하지 않도록 구성할 수 있다.

```text
POST_ID + USER_ID
        ↓
기존 조회 기록 확인
        ↓
조회 기록 없음 → 조회수 증가
조회 기록 있음 → 조회수 유지
```

댓글을 등록하면 댓글 데이터만 저장되는 것이 아니라 원글 작성자에게 보여줄 알림 데이터도 함께 생성된다.

이를 통해 하나의 화면 기능을 구현하기 위해서는 화면뿐만 아니라 Java 로직과 데이터베이스의 관계를 함께 고려해야 한다는 것을 확인하였다.

특히 로그인, 세션, 권한, 보안, AI 추천 등은 구현된 기능을 사용하는 것과 직접 설명하는 것에 큰 차이가 있었다.

또한 프로젝트 발표에서는 단순히 “이 기능을 만들었다”라고 설명하는 것보다 어떤 데이터를 사용하고 어떤 과정을 거쳐 결과가 만들어지는지를 설명할 수 있어야 한다는 것을 알게 되었다.
