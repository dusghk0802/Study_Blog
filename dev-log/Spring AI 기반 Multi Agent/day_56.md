#### 1. 상영 시간표 자동 생성

- 예매 기능을 테스트하려면 모든 극장에 회차가 필요하므로, 서버 시작 시 **상영관과 회차를 자동으로 만드는 시드 서비스** 구현

| 파일 | 역할 |
| --- | --- |
| `ShowtimeScheduleSeedService` | 활성 극장마다 1관~10관, 오늘 포함 7일 치 회차 생성 |
| `ShowtimeScheduleSeedConfiguration` | `@Order(200)`으로 영화 가져오기(`@Order(0)`) 이후 자동 실행 |

- **라인업** : 그날까지 개봉한 영화 중 개봉일 최신 10편 → 새 영화가 개봉하면 가장 오래된 영화가 빠짐
- **상영관 배정과 첫 회차 시간**을 카카오 장소 ID 기반 **해시**로 정해, 극장마다 다르지만 팀원 모두 같은 결과가 나오도록 구성
  - 첫 회차 : `08:00 + (카카오ID·상영관 해시 % 6) × 10분`
  - 회차 간격 : 러닝타임 + 광고 10분 + 청소 20분 (5분 단위 올림)
- 상영관에 `seed_key`(`schedule-v1-1` ~ `schedule-v1-10`) 표식을 붙여 팀원이 만든 기존 상영관은 건드리지 않음
- 이미 만든 시작 시각은 건너뛰어 **여러 번 실행해도 중복이 생기지 않음**
- 극장 하나 단위로 저장 후 `flush()`, `clear()`하여 메모리 사용을 줄임
- 결과 : 67개 극장, 새 회차 **31,555건**을 약 14초에 생성 (좌석 수는 108석 → **120석**으로 수정)

#### 2. 심야 회차 규칙 정리

- 회차 규칙을 여러 번 바꾸며 실제 극장과 비슷한 시간표를 찾아감

| 단계 | 규칙 | 문제 |
| --- | --- | --- |
| 1 | 7회가 다 들어가는 영화만 사용 | 181분인 엔드게임이 시간표에서 빠짐 |
| 2 | 다음 날 첫 회차와 겹치지 않을 때까지 회차 수 줄이기 | 엔드게임 새벽 2시 35분 시작 회차 생성 |
| 3 | 마지막 회차는 새벽 2시 전에 **시작** | 오디세이가 새벽 4시 58분에 끝남 |
| 4 | 마지막 회차는 새벽 3시 30분 전에 **종료** | 일반 영화 7회 유지, 긴 영화만 5회로 자연스럽게 정리 |

- 시작 시간만 제한하면 긴 영화가 너무 늦게 끝나므로, **끝나는 시간**을 기준으로 판단해야 함
- 긴 영화를 따로 예외 처리하지 않고 **규칙 하나로 회차 수가 자동으로 줄어들도록** 구성

#### 3. 영화 상세 정보(장르·감독·출연진) 추가

- TMDB 요청에 `append_to_response=credits`를 추가해 한 번의 요청으로 출연진·제작진까지 가져옴

| 항목 | 저장 방식 |
| --- | --- |
| 장르 | `모험, 액션, 판타지`처럼 쉼표로 연결 |
| 감독 | 제작진 중 `job = Director`인 사람 (최대 2명) |
| 출연진 | 출연 순서(`order`) 기준 상위 5명 |

- 한국어 이름이 없는 배우는 `tmdb.name-overrides` 설정으로 보완
  - `application.properties`는 한글이 깨질 수 있어 **유니코드 이스케이프**(`\uC544\uC624...`)로 작성
- 서버 시작 시 **장르가 비어 있는 영화만** TMDB에서 다시 가져와 자동 보완 → 팀원은 서버만 켜면 적용
- `CatalogResponse.MovieDetail` record에 `genres`, `director`, `castNames` 필드 추가

#### 4. 영화 상세 화면 구현

- 관람등급 표시 함수를 `format.js`로 분리해 **메인 화면과 상세 화면에서 함께 사용** (`15` → `15세`)
- 상세 화면(`MovieHero`)에 표시 추가
  - `15세 · 173분 · 2026.10.11 개봉` 한 줄
  - 장르, 감독·출연진(`<dl>` 태그)
- 관람등급 줄과 장르 줄이 각각 문단이라 여백이 두 번 들어가는 문제 → **같은 문단 안에서 `<br />`로 줄바꿈**하여 간격 정리

#### 5. 상영예정작 개봉일 고정과 기준일 정리

- 서버 시작 시 개봉일이 가장 늦은 10편을 `10/11 ~ 10/17`로 다시 지정하는 코드 때문에, DB에서 개봉일을 고쳐도 재시작하면 다시 덮어써짐
- `tmdb.release-date-overrides=영화번호:개봉일` 설정을 추가해 **지정한 영화는 개봉일을 고정하고 자동 지정에서 제외**
- 개봉일이 같은 영화가 있으면 순서가 매번 달라질 수 있어 **TMDB 번호를 보조 정렬 기준**으로 추가
- 메인 차트 기준일 `app.reference-date`를 비워 **오늘 날짜 기준**으로 변경 → 시간표와 메인 차트가 같은 기준을 사용

#### 6. 극장 화면 목록형으로 변경

- 기존에는 포스터를 누르면 **그 포스터가 있는 줄 바로 아래**에 시간표가 열려, 영화마다 패널 위치가 바뀌는 문제가 있었음
- 국내 극장 사이트처럼 **영화 한 편당 한 줄, 시간표를 처음부터 펼쳐서** 보여주는 목록형으로 변경
- 영화 한 줄을 `TheaterMovieRow` 컴포넌트로 분리
  - 리액트의 **"훅은 컴포넌트 맨 위에서만 호출"** 규칙 때문에 `map` 안에서 `useCatalog`를 직접 부를 수 없음
  - 컴포넌트로 분리하면 영화마다 각자 `/api/showtimes`(`movieId`, `theaterId`, `date`)를 호출
- 시간 카드
  - CSS Grid `repeat(7, minmax(0, 1fr))`로 **한 줄 7칸 고정 크기**
  - 선택 시 카드 전체를 칠하지 않고 포스터 선택과 같은 **노란 테두리 + `선택` 배지** 사용
- 예매 버튼과 안내 문구는 목록 아래 한 곳에 두고, 기존 예매 진행 로직(`useBookingPage`)은 그대로 재사용
- 기존 CSS 변수(`var(--booking-...)`)와 카드 컴포넌트를 그대로 써서 **화면 분위기는 유지하고 배치만 변경**

#### 7. 커밋 관리

- 한 번에 여러 작업을 수정했기 때문에 **작업 단위로 커밋을 나눔**

| 커밋 | 내용 |
| --- | --- |
| `feat` | 영화 상세 화면에 개봉일·장르·감독·출연진 표시 |
| `fix` | 상영예정작 개봉일 고정 및 메인 차트 기준일 수정 |
| `fix` | 상영 시간표 심야 회차 종료 시간 제한 |
| `feat` | 극장 상영시간표를 목록형으로 변경 |

- 시간표 규칙이 바뀌었으므로 팀원에게 **시간표 삭제 SQL 실행 후 서버 재시작**을 함께 공유

#### 9. Troubleshooting

- 장르가 두 번 표시됨 → 새 코드를 추가하면서 **기존 장르 줄을 지우지 않음**
- `LAST_END` 빨간 에러 → 상수 이름을 바꾸지 않고 사용하는 곳만 바꿔 **정의되지 않은 이름** 참조
- 쓰지 않는 `roundsFor()`가 이미 지운 `roundUpTo5Minutes()`를 불러 컴파일 에러 → 사용하지 않는 메서드 삭제
- 오디세이 개봉일을 고쳤는데 계속 상영예정 → `app.reference-date`가 예전 날짜(`2026-07-01`) 그대로였음
- Workbench에서 개봉일을 `NULL`로 바꾼 뒤 서버를 켜도 다시 채워지지 않음
  - 다시 가져올지 판단하는 조건이 **장르만 확인**하기 때문 → 장르를 비우거나 `refresh=true`로 강제 새로고침
- 테스트용 SQL을 한 창에서 전체 실행하면 여러 값이 한꺼번에 지워질 수 있음 → **필요한 줄만 선택해서 실행**

#### 10. 핵심 정리

- 해시 값을 이용해 **극장마다 다르지만 누가 실행해도 같은** 시드 데이터를 만듦
- 표식(`seed_key`)과 중복 확인으로 **여러 번 실행해도 안전한** 데이터 생성 방식을 적용함
- 심야 회차는 시작 시간이 아니라 **종료 시간**을 기준으로 제한해야 자연스러운 시간표가 됨
- 개봉일처럼 자동으로 덮어써지는 값은 **설정값으로 예외를 지정**해 고정함
- 리액트 훅 규칙에 맞게 **반복되는 부분을 컴포넌트로 분리**하고, 기존 스타일을 유지한 채 배치만 변경함

상영 시간표를 자동으로 만들면서 처음에는 회차 수만 맞추면 된다고 생각했지만, 긴 영화가 빠지거나 새벽 늦게 끝나는 회차가 생기면서 실제 극장처럼 보이게 하려면 규칙을 여러 번 다듬어야 한다는 것을 알게 되었다.
</br>특히 시작 시간이 아니라 끝나는 시간을 기준으로 판단해야 한다는 점과, 예외를 하나씩 추가하기보다 규칙 하나로 자연스럽게 정리되도록 만드는 것이 유지보수에 좋다는 점을 배웠다.

극장 화면을 목록형으로 바꾸면서 리액트 훅 규칙 때문에 컴포넌트를 나눠야 하는 이유를 직접 이해할 수 있었고, 팀원이 만든 스타일과 예매 로직을 그대로 살리면서 필요한 부분만 바꾸는 방식으로 작업했다.
