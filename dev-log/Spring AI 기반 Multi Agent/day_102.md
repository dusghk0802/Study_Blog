## 메인 AI 검색과 추천 결과 페이지 구현

📌 학습일 : 2026.11.28

📌 학습 내용 : 자연어 기반 하이브리드 매물 검색, AI 조건 추출과 Oracle·MyBatis 조회 연결, 별도 추천 결과 페이지와 재검색, 매물 비교·자격 안내·고객상담 AI, 맞춤 추천·실시간 알림·정기 수집 안정화

---

#### 1. AI 검색과 실제 매물 조회의 역할을 나눠 하이브리드로 구성했다

WBS 4.10의 메인 AI 검색·챗봇 추천 구현에 선행 착수했다. 기획서와 API 명세에 맞춰 OpenAI·Spring AI가 자연어 문장에서 검색 조건을 추출하고, Spring Boot API가 정제한 조건을 Oracle·MyBatis 기반 매물 조회에 전달하도록 연결했다. 지역·유형·가격·면적처럼 데이터베이스에서 조회할 수 있는 항목만 조건으로 만들고, 값이 없거나 불분명하면 임의로 채우지 않도록 했다.

“조용하고 채광 좋은 집”처럼 모호한 요청은 가격이나 면적을 추측해 필터로 만들지 않는다. 조용함·채광·교통 같은 표현은 확인할 수 있는 선호 기준으로만 사용하고, 엄격한 조건에 맞는 매물이 없으면 진행 중인 매물까지 검색 범위를 넓혀 선택지를 제시한다. AI가 매물의 가격이나 상태를 만들어 내지 않고 데이터베이스가 반환한 결과를 기준으로 보여 주는 구조를 적용했다.

API 명세와 구현에서 개인정보 처리도 확인했다. 검색 대화는 데이터베이스에 저장하지 않고, 회원 식별 정보와 소득·자산·가족 정보는 모델에 보내지 않는다. 검색 종류와 추출 조건도 서버에서 허용된 값인지 검증해 자연어 입력을 바로 SQL에 연결하지 않도록 했다.

#### 2. 홈 검색 결과를 대화가 아닌 별도 매물 페이지에서 보여 주도록 정리했다

홈 검색창에 자연어 조건을 입력하고 검색하면 추천 결과 페이지로 이동한다. 상담용 챗봇과 메인 매물 추천 검색을 분리하고, 홈과 결과 페이지에는 채팅 말풍선이나 대화 입력창을 두지 않았다.

결과 페이지에는 실제 매물 카드와 간단한 추천 이유를 표시한다. 카드에서 지역·유형·진행 상태, 신청 또는 입찰 기간, 가격, 면적을 확인할 수 있고, 추천 이유는 입력 조건과 조회된 매물 정보를 바탕으로 짧게 제공한다. 상세 조건 폼을 공통 검색창으로 바꾸고 결과 페이지 상단에도 계속 표시해, 검색어와 매물 종류를 수정한 뒤 그 자리에서 다시 검색할 수 있도록 했다. 검색창 높이도 기존 60px로 유지했다.

홈에서 결과 페이지로 이동할 때 필요한 검색어·매물 종류·검색 결과는 React Context 상태로 이어 준다. 대화 내용을 영구 저장하지 않는 기획과 화면에서 결과를 다시 찾을 수 있는 편의성을 함께 고려했다.

#### 3. 추천 설명과 사용자 조건·행동을 실제 데이터에 연결했다

메인 추천에서는 사용자가 분명히 말한 조건과 자연어 선호를 구분했다. 지역·유형·예산·면적은 조회 조건으로 반영하고, 주관적인 선호는 확인 가능한 항목 안에서 추천 순서와 설명에 활용한다. 검색 조건과 매물 정보가 맞지 않아 결과 범위를 넓혔을 때는 그 사실을 페이지에 알려 사용자가 결과가 나온 이유를 알 수 있게 했다.

매물 비교에서는 사용자 조건에 맞는 비교 항목을 강조하고 AI 설명을 연결했다. 예상 자격 안내도 공고 조건 항목과 판정 근거가 이어지도록 보완했다. 검색·찜 등 사용자 행동을 맞춤 추천과 홈 배너에 연결하고, 찜 공고 및 회원별 추천 공고 알림을 매칭하는 WBS 4.12 작업도 선행 점검했다. 알림은 SSE 재연결과 읽지 않은 수 갱신 흐름까지 함께 살폈다.

#### 4. 고객상담과 관리자 화면은 메인 추천과 분리해 보완했다

정려립은 AI 고객상담 응답을 SSE로 전달하고, 요청 횟수 제한과 FAQ 대체 응답, 일정 시간 미사용 시 상담 초기화 흐름을 보완했다. FAQ 배치와 질문별 대화 묶음도 정리했다. 메인 AI 매물 추천과 고객상담은 같은 AI 기반을 활용하더라도 목적과 화면·검색 흐름을 분리해야 한다는 점을 확인했다.

청약 프로필 입력에는 본인인증과 PDF 서류 등록 방식 선택을 추가했다. 업로드 파일은 저장하지 않고 7종 서류에서 추출한 값만 암호화해 10분간 보관하도록 했다. 고객센터에서는 관리자 답변을 댓글처럼 표시하고 AI 상담에서 문의로 전환할 때의 필터를 보완했다. 관리자 문의·알림 화면에는 목록에서 상세로 이동하는 흐름과 사이트·이메일 채널 구분을 반영했다.

#### 5. 알림·수집·메일과 홈 화면의 운영 흐름을 다듬었다

실패한 정기 수집 작업을 재시도하도록 보완했다. 재시도 과정에서는 이미 성공한 작업의 중복 실행 여부와 결과를 따로 확인해야 한다는 점을 작업 항목에 남겼다. 메일은 서버가 중단된 동안 기한이 지난 공고 알림을 보내지 않고, Redis에 예약한 마케팅 메일은 재시작 뒤에도 이어서 처리하도록 정리했다.

홈 일정·공지 조회와 표시를 개선했고, 공매 매물 제목에 주소를 보여 주고 선택한 항목으로 이동하도록 수정했다. 계절이나 시간을 바꾼 뒤에도 일조 지도 시점이 유지되도록 보완했다. 오늘 작업을 통해 AI 추천은 조건 추출만 구현해서 끝나는 기능이 아니라 실제 데이터 조회, 결과 설명, 개인정보 보호, 재검색, 실시간 알림과 재시도까지 연결해야 사용자 흐름이 완성된다는 점을 배웠다.
