## 공매 호실 추출 기능과 SpaceLink 프로젝트 문서 정리

📌 학습일 : 2026.11.27

📌 학습 내용 : 공매 감정평가서와 온비드 상세를 활용한 호실 정보 추출, LH 공고 정보 수집 보완, 가격 평가점수 계산, 매물 비교·고객상담 기능 개선, 요구사항·테이블·시퀀스·UI 스토리보드·WBS 정리

---

#### 1. 공매 물건의 건물과 호실 정보를 자동으로 확인하도록 보완했다

오늘은 물건명만으로 건물 전체인지 일부 호실인지 알기 어려운 공매를 보완하는 작업을 진행했다. 온비드 물건 상세와 감정평가서를 확인해 건물 면적과 호실 목록을 추출하고, 물건명에 적힌 호실 수와 비교해 공개할 수 있는지 판단하도록 코드를 수정했다. 추출이 실패하면 확인한 호실 이름을 남겨 관리자가 검토할 수 있게 했다.

다만 실제 공매 자료를 다시 받아 확인하는 과정은 온비드 API 호출 한도에 걸려 끝내지 못했다. 코드가 추가됐다고 실제 데이터까지 정상 처리된 것은 아니어서, 내일 한도가 풀린 뒤 다시 수집해 결과를 확인해야 한다.

#### 2. LH 공고 정보와 매물 점수를 개선했다

LH 공고문에서 건설 위치와 신청 기간을 추출해 공고 상세 정보로 저장하고 화면에 보여 주도록 보완했다. 마이홈 공공임대 공고의 주택형도 상세 페이지에서 실시간으로 확인할 수 있게 해, 수집되지 않았다는 이유만으로 화면에서 빠지지 않도록 했다.

매물 가격 평가점수는 서울 전체에서 같은 용도와 거래 유형을 비교하도록 기준을 정리했다. 임대 매물은 보증금에 월 임대료를 환산해 더한 값을 사용하고, 비교 가격을 5단계로 나눠 점수를 계산하도록 했다. 비교 가능한 자료가 충분하지 않을 때는 점수를 임의로 만들지 않고 확인이 필요한 상태로 남기는 점도 함께 생각했다.

#### 3. 매물 비교와 고객상담, 관리자 수집 화면을 보완했다

매물 비교 화면에는 후보 위치를 지도 핀으로 표시하고, 비교할 후보가 아직 없을 때도 빈 비교표가 보이도록 정리했다. 예상 자격 결과에서는 어떤 공고 조건을 근거로 판단했는지 항목 이름이 나타나도록 수정했다.

AI 고객상담은 서비스 기능을 묻는 질문에 관련 기능과 이용 안내 바로가기를 제공하도록 보완했다. 관리자 수집 화면에서는 자동 처리 중인 공고나 공매가 실패 목록에 중복으로 보이지 않도록 했고, 마감됐거나 좌표를 찾은 물건의 수집 오류는 자동으로 처리 완료할 수 있게 했다. 소음 분석은 측정 지점을 다시 찾고, 측정값과 소음원이 모두 없는 경우에도 결과가 비어 버리지 않도록 보완했다.

#### 4. 요구사항과 설계 문서를 실제 구현 흐름에 맞춰 정리했다

오늘 수정한 요구사항 정의서, 테이블 정의서, 핵심 기능 시퀀스 흐름 정의서, UI 스토리보드, WBS를 함께 살펴봤다. 공고 조건 추출은 원문 수집과 문서 처리 뒤 AI가 검토용 초안을 만들고, 관리자가 확인·승인한 다음에야 자격 판정에 반영되는 흐름으로 정리했다. 승인 전 조건이나 자료가 빠진 항목은 확정된 값처럼 표시하지 않고 확인 필요로 안내하도록 했다.

테이블 정의에는 공매 문서의 종류와 파일 형식, 묶음 물건과 호실 정보, 가격 평가점수 같은 구현 항목을 반영했다. 화면 정의서에는 공고 상세의 조건·점수·준비서류 표시와 매물 비교 화면 흐름을 정리했다. 문서끼리 같은 기능을 서로 다르게 설명하지 않도록 요구사항, 데이터 구조, 화면, 처리 순서를 함께 맞추는 일이 중요하다는 걸 배웠다.

#### 5. 완료 표시와 실제 검증 결과를 따로 확인해야 한다

WBS에는 공고 조건·호실 추출 작업이 완료로 표시돼 있지만, 오늘 공매 수집은 API 호출 한도로 실제 검증을 마치지 못했다. 그래서 문서나 코드에 기능이 반영된 상태와 실제 자료를 끝까지 처리한 상태를 구분해야 한다는 점을 다시 확인했다. 내일 공매 수집을 재시도한 뒤 추출 결과와 관리자 승인, 승인 후 자격 재판정까지 확인하고 WBS 상태도 실제 결과에 맞게 정리해야겠다.

오늘은 기능을 구현하는 일과 그 기능이 실제 데이터에서 동작하는지 증명하는 일이 별개라는 걸 배웠다. 특히 공매처럼 외부 API 호출 한도에 영향을 받는 작업은 호출 결과와 실패 원인을 기록하고, 재시도 가능한 시점을 기다려 검증을 이어가야 한다. 요구사항과 화면, DB 구조, 처리 흐름도 실제 구현과 함께 맞춰야 다음 작업에서 혼란이 줄어들 것 같다.
