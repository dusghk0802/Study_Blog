# 55일차

## 미니프로젝트 누적관객수·예매율 구현 및 메인 영화 차트 개발

📌 학습일 : 2026.10.01

📌 학습 내용 : Counter Column, Atomic Update, Derived Query, Record DTO, Reference Date, React, HorizontalRail, Merge Conflict, Branch Strategy

#### 1. 메인 차트 정렬 기준 결정

- 원래 기획은 **예매율 순** 정렬이지만, 예매 데이터가 가상이라 처음에는 모든 영화가 0으로 순위가 무의미
- 해결 방법으로 **누적관객수 카운터 컬럼** 방식 선택
  - 초기값은 설정 파일로 직접 입력
  - 우리 사이트에서 예매 확정 시 증가, 취소 시 감소
- **예매율은 저장하지 않고 조회 시 계산** : `이 영화 누적관객수 ÷ 전체 누적관객수 합 × 100`
  - 한 영화가 예매되면 다른 영화의 예매율도 함께 바뀌므로 저장하면 모든 행을 다시 갱신해야 함

| 구분 | 조건 | 정렬 | 개수 |
| --- | --- | --- | --- |
| 상영작 | 개봉일 ≤ 기준일 | 누적관객수 많은 순 → 개봉일 최신순 | 10편 |
| 상영예정작 | 개봉일 > 기준일 | 개봉일 빠른 순 → 제목순 | 10편 |

- 값이 같은 경우를 대비해 **보조 정렬 기준**을 함께 지정 (모두 0이면 순서가 매번 달라질 수 있음)

#### 2. 누적관객수 구현

| 파일 | 변경 내용 |
| --- | --- |
| `Movie` | `audience_count` 컬럼 추가 (기본값 0) |
| `application.properties` | `tmdb.audience-seeds=영화번호:관객수,...` 초기값 설정 |
| `MovieImportService` | 영화 저장 시 초기값 적용, 기존 영화 초기값 보완 메서드 추가 |
| `MovieRepository` | 누적관객수 증감 쿼리 `updateAudienceCount()` |

- 이미 저장된 영화는 가져오기를 건너뛰어 초기값이 들어가지 않는 문제 발생
  - Workbench로 데이터를 지우면 **내 DB만** 해결되므로, 서버 시작 시 **누적관객수가 0이거나 등급이 비어 있는 영화만** 설정값으로 채우도록 구현
  - 팀원도 서버만 켜면 동일하게 적용되고, 이미 값이 있으면 덮어쓰지 않음
- 증감은 동시 예매 시 값이 덮어써지지 않도록 **DB에서 한 번에 계산하는 쿼리** 사용
  - `UPDATE Movie m SET m.audienceCount = m.audienceCount + :delta WHERE m.id = :movieId AND m.audienceCount + :delta >= 0`
  - 차감 결과가 0 미만이면 변경하지 않아 **음수 방지**
- 증감 메서드는 예매 담당 팀원이 **예매 확정·취소 트랜잭션 안에서** 호출하도록 공유

#### 3. 메인 차트 API 구현

- `GET /api/main` 하나로 **상영작(`nowShowing`) + 상영예정작(`comingSoon`)** 두 목록을 함께 반환
- 정렬과 10편 제한을 자바가 아닌 **메서드 이름 기반 쿼리**로 처리
  - `findTop10ByActiveTrueAndReleaseDateLessThanEqualOrderByAudienceCountDescReleaseDateDesc()`
  - `findTop10ByActiveTrueAndReleaseDateAfterOrderByReleaseDateAscTitleAsc()`
- 예매율 분모는 `sum()` 집계 쿼리로 한 번에 조회하여 전체 영화를 불러오지 않음
- 고정 날짜로 테스트하기 위해 **기준일 설정** `app.reference-date` 추가 (비우면 오늘 날짜)
  - `LocalDate`는 날짜 타입일 뿐이고, 현재 날짜는 `LocalDate.now()`일 때만 사용됨
- 응답 DTO를 빌더 클래스 대신 **record**로 정리하고 `posterUrl`, `releaseDate` 필드 반영

---

#### 4. 메인 페이지 화면 구현

- 화면 설계 담당 팀원이 레퍼런스(Pathé)를 참고해 만든 **대표 영화 배너 + 가로 목록(`HorizontalRail`)** 구조를 그대로 사용
- 기존 데이터 조회 도구 `useCatalog('main', {})`로 메인 차트 API 호출
- 한 줄에 모든 영화가 표시되던 목록을 **상영작 / 상영예정작 두 줄**로 분리하고 페이지 이동 제거
- 카드 표시 정보
  - 관람등급이 숫자면 `세`를 붙여 표시 (`15` → `15세`, `ALL`은 그대로)
  - 상영작 : 누적관객수와 예매율 / 상영예정작 : 개봉일
- 포스터가 없으면 대체 화면을 보여주는 팀원의 기존 처리 유지

#### 5. 브랜치 관리

- 작업 성격에 맞춰 브랜치를 분리
  - `feat/movie-audience-count` : 누적관객수 기능 (예매 담당 팀원이 바로 쓸 수 있도록 먼저 병합)
  - `feat/main-page` : 메인 차트 API와 화면
- 새 브랜치는 항상 **최신 main을 Pull한 뒤** 생성
- main 변경 사항을 작업 브랜치로 가져오는 중 `HomePage.jsx` 충돌 발생 → 팀원 버전(`Use the modified file from main`)을 선택하고 병합 계속 진행

#### 6. 테스트 결과

- 서버 재시작 시 기존 20편에 초기 누적관객수가 채워지고, 재실행 시 다시 덮어쓰지 않음 확인
- Postman으로 `GET /api/main` 호출 → `nowShowing`, `comingSoon` 두 목록과 정렬 순서 확인
- 브라우저에서 상영작·상영예정작 두 줄과 관람등급, 누적관객수, 예매율, 개봉일 표시 확인

---

#### 7. Troubleshooting

- 팀원이 패키지 이름을 `smartticketing`으로 변경한 뒤 `ClassNotFoundException` 발생 → 실행 구성의 **기본 클래스**를 새 경로로 다시 선택
- 생성자 매개변수에 `@Value("${tmdb.audience-seeds:}")`가 빠져 컴파일 에러 → 매개변수 추가
  - 다른 파일에서 이 클래스를 사용하는 곳에 문제가 생기면 IntelliJ의 **"관련 문제"** 표시로 확인 가능
- 팀원이 같은 파일(`MovieImportService`)에 예고편 기능을 추가해 둔 상태 → 전체 코드 교체 대신 **현재 코드를 기준으로 필요한 부분만 추가**

---

#### 8. 핵심 정리

- 실제 예매 데이터가 없을 때 **초기값 + 예매 시 증감하는 카운터 컬럼**으로 순위를 만드는 방법을 설계함
- 예매율처럼 다른 값에 따라 바뀌는 비율은 **저장하지 않고 조회 시 계산**함
- 동시 요청에도 값이 정확하도록 **DB에서 바로 더하는 쿼리**와 음수 방지 조건을 적용함
- 정렬·개수 제한을 **메서드 이름 기반 쿼리**로 처리하고, 기준일을 설정값으로 분리함
- 팀원의 화면 구조를 재사용하여 **상영작·상영예정작 목록**을 분리 표시함

메인 차트를 만들면서 예매율 순으로 정렬하려 했지만 가상 데이터라 순위가 의미 없다는 문제를 마주했고, 초기값을 넣고 예매할 때마다 늘어나는 누적관객수로 순위와 예매율을 함께 해결할 수 있었다.
</br>특히 예매율처럼 다른 영화에 따라 바뀌는 값은 저장하지 않고 계산해야 한다는 점과, 여러 명이 동시에 예매해도 숫자가 틀어지지 않도록 쿼리를 작성해야 한다는 점을 배웠다.

팀원들이 같은 파일과 패키지를 함께 수정하면서 실행 설정 오류와 병합 충돌을 겪었는데, 전체 코드를 덮어쓰기보다 현재 코드를 확인하고 필요한 부분만 고치는 것이 협업에서 중요하다는 것을 느꼈다.
</br>다음에는 예매 담당 팀원과 누적관객수 증감을 연결하고, 극장 정보와 상영 시간표 기능을 이어서 만들 예정이다.
